# 📝 기존 컨텐츠 변환 및 리팩토링 지침 (Convert Page Instructions)

이 스킬은 기존 기술 문서를 정보 누락 없이 최신 마스터 템플릿 기반의 웹 문서로 리팩토링하기 위한 4단계 프로세스 및 백업/정리 관리 규칙을 정의합니다.

기본 레이아웃, 시각화 우선순위, 기술 스택 및 템플릿 규격은 **[create-page 스킬](../create-page/SKILL.md)**의 지침을 공유하고 참조합니다.

---

## 1. 파일 백업 및 저장 규칙 (Backup Strategy)

기존 HTML 파일이나 문서를 리팩토링할 때는 원본 데이터의 안전 보존을 위해 반드시 다음 작업을 이행한다:
1. **기존 파일 백업**: 기존 원본 파일의 이름을 `[파일명]_백업.html` (예: `ptq.html` -> `ptq_백업.html`)으로 변경하거나 백업 사본을 생성한다.
2. **신규 결과물 저장**: 4단계 워크플로우를 거쳐 새롭게 변환된 리팩토링 결과물은 원래 파일명인 `[파일명].html`로 저장한다.
3. **완료 후 백업 삭제**: 사용자로부터 리팩토링 최종 완료 확인을 받으면 생성했던 백업 파일(`[파일명]_백업.html`)을 삭제한다.

---

## 2. 변환 4단계 워크플로우

### 1단계: 원문 분석 및 정보 추출 (Extraction)
- 재작성 전, 원문의 핵심 데이터, 기술적 개념, 단계별 절차, 수치를 빠짐없이 리스트업한다.
- **목적**: 정보 누락 방지 (이 단계에서는 문체를 고려하지 않고 추출에 집중한다).

### 2단계: 시각적 구조화 및 재작성 (Rewriting)
- 추출된 정보를 바탕으로 마스터 템플릿 스택을 활용해 재작성한다.
- **시각화 원칙**: [create-page 스킬](../create-page/SKILL.md)의 5단계 시각적 우선순위(시뮬레이션 > 그래프 > 표 > 목록 > 일반 텍스트) 및 규정을 적용한다.
- **문체 규정**: "~한다" 형태의 평어체를 사용하며, 목록과 테이블은 명사 또는 명사형으로 종결한다.

### 3단계: 무결성 검증 (Verification)
- 원문과 최종 결과물을 1:1 대조하여 정보 누락이나 임의 수정 여부를 체크한다.
- **자가 검증 필수 체크리스트**: 대조표 작성 전 다음 세 가지 규칙을 스스로 엄격하게 진단하고 교정한다.
  - **14px 폰트 하한선 룰과 SVG 레이아웃 정합성**: 전역 `max(14px, 1em) !important` 규칙에 의해 SVG 내부의 `text` 및 `tspan`이 강제 확대되어 박스 테두리를 벗어나거나 레이아웃이 깨지지 않는지 검증한다. 텍스트가 겹치거나 넘친다면 폰트를 강제로 줄이는 대신 SVG 내부 박스(rect)의 `width`/`height`를 키우고 Y축 좌표를 넉넉하게 재배치하여 수용 공간을 물리적으로 확보해야 한다.
  - **원문 문구 보존 (의역/요약 금지)**: 다이어그램 내부 문구, 수식, 핵심 단어들을 자연스러운 문장으로 다듬는다는 이유로 임의로 패러프레이징(말바꾸기)하지 말고, 원형 그대로 100% 온전히 보존한다.
  - **코드 편집 범위 중복 방지**: 편집 툴 사용 과정에서 범위 조절 실수로 인해 동일한 HTML 요소(예: 입력 노드 등)가 중복으로 겹쳐서 삽입되지 않았는지 코드 라인 정합성을 재검토한다.
- **검증 대조표 작성**: 결과물 최하단에 HTML Table 형식으로 아래 항목이 포함된 검증 대조표를 작성하여 추가한다.
  - `| 핵심 항목 | 원문 내용 | 재작성 상태 | 일치 여부 | 변경 사유 |`
- 검증 중 부적절한 누락이나 훼손이 발견될 경우 해당 섹션을 즉시 수정하여 반영한다.

### 4단계: 최종 승인 및 정리 (Cleanup)
- 사용자로부터 리팩토링 결과물에 대한 완료 확인(승인)을 받으면 다음 정돈 작업을 수행한다:
  1. **검증 대조표 삭제**: `[파일명].html` 최하단에 포함시킨 무결성 검증 대조표(HTML Table)를 삭제하고 문서를 최종 저장한다.
  2. **백업 파일 삭제**: 생성했던 원본 백업 파일(`[파일명]_백업.html`)을 삭제한다.

## 3. 공통 기술 제약 및 레이아웃 참조

다음 항목들은 **[create-page 스킬](../create-page/SKILL.md)**에 정의된 규격을 참조하여 동일하게 적용한다:

- **프레임워크 & 스택**: Bootstrap 5, Highlight.js (atom-one-light 테마), 17px Fira Code (`text-align: left !important`)
- ⚠️ **LaTeX 표기법 절대 사용 금지**: KaTeX, MathJax 등 LaTeX 수식 라이브러리 및 LaTeX 표기법(`$...$`, `$$...$$`)은 **절대 절대 사용 금지**. 수식 및 연산 복잡도는 HTML 태그(`<sup>`, `<sub>`, `<code>`)로 직접 표현
- **화면 규격**: 너비 1280px 반응형 컨테이너, 배경 `#FFF`, 글자 `#000`, 18px Pretendard 폰트
- **필수 스크립트**: 문서 최하단(`</body>` 바로 직전) Iframe 높이 조절 스크립트 필수 포함
- 🚨 **마스터 템플릿 철저 준수 (Strict Template Compliance)**: [create-page/resources/template.html](../create-page/resources/template.html)의 마크업 구조, CSS 변수(`:root { --primary: #0d6efd; --kw: #d63384; }`), 플로팅 목차(TOC Drawer) HTML/CSS, 문서 헤더(`<h1>`), 섹션 제목(`<h2>`), 코드 블록(`pre code`), 요약 박스(`<footer id="summary" class="summary-box">`) 구조를 **임의로 변경하거나 탈피하지 말고 100% 엄격하게 준수**하여 리팩토링 및 변환한다.
