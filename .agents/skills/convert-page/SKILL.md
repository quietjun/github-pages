# 📝 기존 컨텐츠 변환 및 리팩토링 지침 (Convert Page Master Guide)

본 지침은 기존 기술 문서를 정보 누락 없이 최신 마스터 템플릿 기반 웹 문서로 리팩토링하기 위한 4단계 변환 워크플로우, 백업 전략, 무결성 자가 검증 체크리스트 및 정리 규칙을 정의합니다.

기본 레이아웃, 시각화 우선순위, 기술 스택 및 템플릿 규격은 **[create-page 스킬](../create-page/SKILL.md)** 및 **[resources/template.html](../create-page/resources/template.html)**을 참조하여 100% 동기화합니다.

---

## 1. 파일 백업 및 저장 규칙 (Backup Strategy)

기존 HTML 파일이나 문서를 변환/리팩토링할 때는 원본 데이터의 안전 보존을 위해 반드시 다음 3단계를 엄격히 이행한다:

1. **기존 파일 백업 사본 생성**: 기존 원본 파일명을 `[파일명]_백업.html` (예: `rnn.html` ➔ `rnn_백업.html`)으로 변경하거나 백업 사본을 생성한다.
2. **신규 리팩토링 결과물 저장**: 4단계 워크플로우를 거쳐 변환된 신규 결과물은 원래 파일명인 `[파일명].html`로 저장한다.
3. **최종 승인 후 백업 삭제**: 사용자로부터 리팩토링 최종 승인을 받으면 검증 대조표와 백업 파일(`[파일명]_백업.html`)을 삭제하고 정리한다.

## 2. 변환 4단계 워크플로우 (4-Step Conversion Workflow)

### 1단계: 원문 분석 및 정보 추출 (Extraction)
- 재작성 전 원문의 핵심 기술 개념, 수식, 시뮬레이션 동작 단계, 수치를 빠짐없이 리스트업한다.
- **목적**: 정보 누락 방지 (이 단계에서는 문체를 다듬지 않고 핵심 원문 데이터 추출에 집중한다).

### 2단계: 시각적 구조화 및 재작성 (Rewriting)
- 추출된 정보를 바탕으로 **[create-page 스킬](../create-page/SKILL.md)**의 5단계 시각화 우선순위(시뮬레이션 > 그래프 > 표 > 목록 > 일반 텍스트)를 채택하여 재작성한다.
- **카드 및 레이아웃 규칙**:
  - **이중 중첩 카드 금지 (Card-in-Card 금지)**: 2중/3중 겉틀 카드 상자 중복 사용을 금지하고 단일 카드 겉틀 내부에 Bootstrap Grid(`row g-3`) 및 배경 블록(`p-3 bg-light rounded-3`)으로 위계 구성한다.
  - **단일 아이콘 룰**: FontAwesome 아이콘과 이모지를 중복 사용하지 않고 1개의 전용 아이콘만 표기한다.
  - **컨트롤 버튼 높이 통일**: 시뮬레이션 버튼과 배지 높이(`31px`) 및 여백(`gap-2`)을 통일한다.

### 3단계: 무결성 검증 및 자가 체크리스트 (Verification)
- 원문과 결과물을 1:1 대조하여 정보 누락이나 임의 수정 여부를 체크한다.
- **🚨 5대 엄격 자가 검증 체크리스트**:
> [!CAUTION]
> **🚨🚨🚨 [최우선 절대 준수] SVG 1:1 무축소(Zero Scale-Down) 및 수용 상자 계산 4대 절대 금기 🚨🚨🚨**
> 1. **절대 금기 1: 광활한 viewBox(900px+) 지정으로 브라우저 Scale-Down 유발 엄금**
>    - SVG `viewBox` 가로 폭은 실제 HTML 컨테이너(Bootstrap col) 너비와 **1:1로 100% 일치**해야 한다.
>    - 컨테이너가 `780px`이면 `viewBox="0 0 780 ..."` / `col-lg-9`(620px)이면 `viewBox="0 0 620 ..."` 필수.
>    - viewBox 폭을 900px, 965px 등으로 설정하여 14px 글자가 화면에서 11px~12px로 축소되는 현상은 **100% 렌더링 결함**이다.
> 2. **절대 금기 2: SVG `<text>` 요소 내부 HTML 태그(`<sub>`, `<sup>`, `<div>`) 사용 금지**
>    - SVG `<text>` 요소 안에는 HTML 태그(`<sub>`, `<sup>`, `<div>`)를 절대로 넣을 수 없다. (넣을 경우 브라우저가 SVG 렌더링을 완전히 파괴하고 텍스트를 바닥으로 쏟아냄).
>    - 수식/첨자는 텍스트 분리, SVG `<tspan font-size="14" dy="3">`, 유니코드(t-1, t, t+1) 또는 평문 처리한다.
> 3. **절대 금기 3: 폰트(14px) 수용 공간(원 r=28+, rect 너비) 부실 설정 금지**
>    - 글자 크기가 14px이면 이를 담는 **원(circle)의 반지름은 무조건 `r=28` 이상(지름 56px+)**, rect 너비도 넉넉하게 확장하여 글자 양옆으로 **최소 10px 이상의 시각적 여백(Breathing Room)**을 확보한다.
> 4. **절대 금기 4: 작업 후 1:1 물리적 렌더링 검수 생략 금지**
>    - 작성 완료 후 반드시 브라우저 본문 글자(16px) 대비 SVG 내부 글자(14px)가 축소 없이 1:1 원본 비율 그대로 보이고 겹침이 없는지 최종 검증한다.
  4. **단일 아이콘 룰 (이중 중첩 금지)**: 헤더 및 카드 제목에 FontAwesome 아이콘과 이모지를 이중 중복으로 배치하지 않는다.
  5. **원문 문구 보존 (의역/요약 금지)**: 다이어그램 내부 문구, 수식, 핵심 단어들을 임의로 패러프레이징(말바꾸기)하지 말고 원형 그대로 100% 온전히 보존한다.
- **검증 대조표 작성**: 결과물 최하단에 HTML Table 형식으로 대조표를 작성하여 포함시킨다:
  - `| 핵심 항목 | 원문 내용 | 재작성 상태 | 일치 여부 | 변경 사유 |`

### 4단계: 최종 승인 및 정리 (Cleanup)
- 사용자로부터 리팩토링 결과물에 대한 최종 완료 승인을 받으면 다음 정돈 작업을 수행한다:
  1. **검증 대조표 삭제**: `[파일명].html` 최하단의 무결성 검증 대조표(HTML Table)를 삭제하고 저장한다.
  2. **백업 파일 삭제**: 원본 백업 파일(`[파일명]_백업.html`)을 삭제한다.

## 3. 공통 기술 제약 및 마스터 템플릿 연계

다음 항목들은 **[create-page 스킬](../create-page/SKILL.md)** 및 **[resources/template.html](../create-page/resources/template.html)**의 규격을 참조하여 동일하게 적용한다:

- **프레임워크 & 스택**: Bootstrap 5, Highlight.js (atom-one-light 테마), 17px Fira Code (`text-align: left !important`)
- ⚠️ **LaTeX 표기법 절대 사용 금지**: KaTeX, MathJax 등 LaTeX 수식 라이브러리 및 LaTeX 표기법(`$...$`, `$$...$$`)은 **절대 절대 사용 금지**. 수식 및 연산 복잡도는 HTML 태그(`<sup>`, `<sub>`, `<code>`)로 직접 표현한다.
- **화면 규격 & 키워드**: 너비 1280px 반응형 컨테이너, 배경 `#FFF`, 글자 `#000`, 18px Pretendard 폰트, `<span class="kw">` 분홍색 굵은 기울임 강조
- **필수 스크립트**: 문서 최하단 (`</body>` 직전) Highlight.js 및 Iframe 높이 조절 (`window.parent.postMessage`) 스크립트 필수 포함
- 🚨 **마스터 템플릿 철저 준수 (Strict Template Compliance)**: 마크업 구조, CSS 변수(`:root { --primary: #0d6efd; --kw: #d63384; }`), 플로팅 목차(TOC Drawer) HTML/CSS, 문서 헤더(`<h1>`), 섹션 제목(`<h2>`), 코드 블록(`pre code`), 요약 박스(`<footer id="summary" class="summary-box">`) 구조를 **임의로 바꾸지 않고 100% 철저히 준수**하여 리팩토링한다.
