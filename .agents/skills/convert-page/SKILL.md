# 📝 기존 컨텐츠 변환 및 리팩토링 지침 (Convert Page Instructions)

이 스킬은 기존 기술 문서를 정보 누락 없이 최신 마스터 템플릿 기반의 웹 문서로 리팩토링하기 위한 3단계 프로세스 및 백업 관리 규칙을 정의합니다.

기본 레이아웃, 시각화 우선순위, 기술 스택 및 템플릿 규격은 **[create-page 스킬](../create-page/SKILL.md)**의 지침을 공유하고 참조합니다.

---

## 1. 파일 백업 및 저장 규칙 (Backup Strategy)

기존 HTML 파일이나 문서를 리팩토링할 때는 원본 데이터의 안전 보존을 위해 반드시 다음 작업을 이행한다:
1. **기존 파일 백업**: 기존 원본 파일의 이름을 `[파일명]_백업.html` (예: `ptq.html` -> `ptq_백업.html`)으로 변경하거나 백업 사본을 생성한다.
2. **신규 결과물 저장**: 3단계 워크플로우를 거쳐 새롭게 변환된 리팩토링 결과물은 원래 파일명인 `[파일명].html`로 저장한다.

---

## 2. 변환 3단계 워크플로우

### 1단계: 원문 분석 및 정보 추출 (Extraction)
- 재작성 전, 원문의 핵심 데이터, 기술적 개념, 단계별 절차, 수치를 빠짐없이 리스트업한다.
- **목적**: 정보 누락 방지 (이 단계에서는 문체를 고려하지 않고 추출에 집중한다).

### 2단계: 시각적 구조화 및 재작성 (Rewriting)
- 추출된 정보를 바탕으로 마스터 템플릿 스택을 활용해 재작성한다.
- **시각화 원칙**: [create-page 스킬](../create-page/SKILL.md)의 5단계 시각적 우선순위(시뮬레이션 > 그래프 > 표 > 목록 > 일반 텍스트) 및 규정을 적용한다.
- **문체 규정**: "~한다" 형태의 평어체를 사용하며, 목록과 테이블은 명사 또는 명사형으로 종결한다.

### 3단계: 무결성 검증 (Verification)
- 원문과 최종 결과물을 1:1 대조하여 정보 누락이나 임의 수정 여부를 체크한다.
- **검증 대조표 작성**: 결과물 최하단에 HTML Table 형식으로 아래 항목이 포함된 검증 대조표를 작성하여 추가한다.
  - `| 핵심 항목 | 원문 내용 | 재작성 상태 | 일치 여부 | 변경 사유 |`
- 검증 중 부적절한 누락이나 훼손이 발견될 경우 해당 섹션을 즉시 수정하여 반영한다.

## 3. 공통 기술 제약 및 레이아웃 참조

다음 항목들은 **[create-page 스킬](../create-page/SKILL.md)**에 정의된 규격을 참조하여 동일하게 적용한다:

- **프레임워크 & 스택**: Bootstrap 5, Highlight.js (atom-one-light 테마), 17px Fira Code (`text-align: left !important`)
- **화면 규격**: 너비 1280px 반응형 컨테이너, 배경 `#FFF`, 글자 `#000`, 18px Pretendard 폰트
- **필수 스크립트**: 문서 최하단(`</body>` 바로 직전) Iframe 높이 조절 스크립트 필수 포함
- **기본 템플릿**: [create-page/resources/template.html](../create-page/resources/template.html) 구조 기반 작성
