BertWordPieceTokenizer

학습되지 않은 빈 토크나이저 생성 → WordPiece 알고리즘으로 서브워드 분리 과정 시각화

이번 포스트에서는 Hugging Face의 tokenizers 라이브러리를 활용하여 학습되지 않은 빈 BertWordPieceTokenizer를 생성하고, WordPiece 알고리즘을 통해 서브워드(Subword)로 분리하고 Vocab을 구축하여 인코딩하는 전체 과정을 시각적으로 분석해 본다.
🗂️ BertWordPieceTokenizer의 설계
① 정의 : 서브워드(Subword) 토큰화
단어(Word)보다 작고 문자(Character)보다 큰 ‘의미 있는 조각’ 단위로 단어를 분리하여 사전을 구축하는 방식이다. 컴퓨터가 인간의 언어를 분석할 때 단어 단위와 문자 단위가 가지는 고유한 문제점들을 극복하기 위한 현대 자연어 처리(NLP)의 표준적인 기법이다.
② 방법 : 연속 서브워드 접두사(##) 부착
단어 내의 첫 번째 서브워드를 제외한 나머지 연속된 조각들에는 ## 접두사를 부착하여 단어 시작 위치를 구분한다.
  • 예: "playing" ➡️ play + ##ing / "고양이가" ➡️ 고양이 + ##가
  • 이 표식을 통해 띄어쓰기 없이 결합한 복합어, 조사, 어미 등의 연결 관계를 원형대로 온전하게 복원할 수 있다.
③ 특징 : 기존 토큰화 방식 대비 효과
구분 상세 설명
단어 단위의 한계 극복 파생어나 조사 결합형(공부, 공부하다, 공부는 등)을 모두 사전에 개별 등록할 필요가 없어 사전(Vocab) 크기가 폭발하는 현상을 방지한다.
문자 단위의 한계 극복 단어를 낱글자로만 완전히 해체하여 의미를 유실하거나 문맥 이해에 필요한 토큰 시퀀스의 길이가 과도하게 길어지는 문제를 방지한다.
OOV(Out-Of-Vocabulary) 해결 사전에 없는 낯선 단어도 자주 쓰이는 서브워드(어근, 접사 등) 블록들의 결합으로 조합하여 의미를 올바르게 유추할 수 있다.
📚 BertWordPieceTokenizer 활용
Method Signature
tokenizer.train( files: Union[str, List[str]], vocab_size: int = 30000, min_frequency: int = 2, special_tokens: List[str] = ["[PAD]", "[UNK]", "[CLS]", "[SEP]", "[MASK]"], limit_alphabet: int = 1000, initial_alphabet: List[str] = [], wordpiece_prefix: str = "##" )
vocab_size default: 30,000
WordPiece 학습 완료 후 최종 토큰 목록의 총 크기이다.
자주 등장하는 서브워드 쌍을 병합하다가 이 수에 도달하면 학습을 종료한다.
  • 너무 작으면 → 병합 조기 종료 → 짧은 서브워드·문자 단위 토큰 다수 잔존 → 시퀀스가 길어짐 → 연산량 증가
  • 너무 크면 → 희귀 단어도 vocab에 포함되어 메모리 및 학습 비용 증가
  • BERT 기본값 30,000 : 영어 기준 균형점이며, 한국어는 형태소의 다양성으로 인해 더 큰 값 사용을 권장한다.
min_frequency default: 2
서브워드 쌍(pair)을 병합할 때 적용되는 최소 등장 빈도 조건이다.
  • 인접 서브워드 쌍이 이 값 이상 등장해야만 병합 후 vocab에 추가된다.
  • 기본값은 2이며, 딱 1번만 붙어서 등장한 쌍은 병합하지 않는다.
    • 예쁘 + ##ㅂ니다 가 1회 등장 ➡️ 병합하지 않음
    • 고양이 + ##가 가 여러 문장에서 2회 이상 인접해서 등장 ➡️ 고양이가로 병합
  • 개별 문자(base vocab)에는 미적용 : 학습 데이터에 단 1번만 등장해도 문자는 vocab에 무조건 등록한다.
special_tokens
특수 토큰 목록을 직접 지정한다. BERT의 기본 5종은 다음과 같다.
  • [PAD] : 배치 처리 시 시퀀스 길이를 맞추기 위한 패딩 토큰이다.
  • [UNK] : vocab에 없는 OOV(Out-Of-Vocabulary) 단어를 대체하는 토큰이다.
  • [CLS] : 문장의 시작을 알리며, 분류(Classification) 태스크에서 문장 전체의 표현(Representation)으로 활용한다.
  • [SEP] : 두 문장 사이의 구분자 또는 문장 경계를 표시하는 토큰이다.
  • [MASK] : MLM 학습 시 마스킹된 위치를 나타내는 토큰이다.
limit_alphabet default: 1,000
단어가 아니라 '낱글자(개별 문자)' 단위로 초기 base vocab에 등록될 문자의 최대 개수 상한선이다.
  • 학습 데이터 전체에서 빈도가 가장 낮은 문자부터 순서대로 제외되며, 제외된 문자는 추론 시 [UNK]로 처리될 수 있다.
initial_alphabet
학습 전에 vocab에 미리 추가해 둘 문자(character) 집합이다.
  • 학습 데이터에 등장하지 않아도 반드시 포함시켜야 하는 문자를 지정할 수 있다.
  • 특수 토큰([CLS], [SEP] 등)은 별도 special_tokens 인자로 추가하므로 initial_alphabet과 구분된다.
wordpiece_prefix default: '##'
단어 내 첫 번째 위치가 아닌 연속 서브워드임을 표시하는 접두사이다.
  • "playing" → play + ##ing
  • "unbelievable" → un + ##believ + ##able
  • 첫 서브워드에는 ##이 붙지 않으므로 단어의 시작 위치를 명확히 구분할 수 있다.

③ 인접 문자 쌍 병합
단어를 문자 단위로 분리한다. 이때 첫 문자는 그대로 두고, 나머지는 ## 접두사를 붙인다.

2회 ✓ → 강아로 병합한다.
앵##무

④ 더 긴 서브워드 병합
이미 병합된 서브워드끼리 다시 빈도를 계산하여 더 긴 서브워드를 생성한다.

특성 고려

🔢 토큰 ID 변환
토크나이저는 각 토큰을 vocab에서의 인덱스(정수)로 변환한다. 이는 단순 정수 인덱스 구조로 해당 토큰의 행 번호를 그대로 가져와 사용한다.
텍스트 → 토큰 → ID 변환 예시
"고양이가 좋아요" →
고양이가 좋아요
→ [1523, 892]
"강아지가 귀여워요" →
강아지가 귀여워요
→ [884, 731]
⚖️ nn.Embedding(밀집 벡터)의 필요성
토큰 ID를 학습 가능한 고정된 차원의 실수 벡터(밀집 벡터)로 변환한다.
❌ 단순 정수 인덱스의 한계
고양이가 (ID=1523)
→ 단순 정수 Index [1523]
→ 단순 정수 인덱스는 단지 '식별자'일 뿐, 문자 간의 유사도나 관계를 연산할 수 없다. (예: 1523과 1524가 의미상 가깝다고 할 수 없음)
✅ nn.Embedding (밀집 벡터) 변환의 이점
고양이가 (ID=1523) → [0.12, -0.34, 0.88, …]
(768차원 실수 밀집 벡터)
→ 차원 축소 : 수만 차원이 아닌 고정된 크기(예: 768차원)로 표현하여 메모리 사용량을 대폭 절감한다. → 의미 정보 학습 : 모든 차원이 실수값으로 구성되어, 유사한 단어끼리 유사한 벡터 공간에 위치하도록 단어 간의 유기적 유사성과 의미를 학습할 수 있다.
📖 nn.Embedding 동작 원리
임베딩 레이어(nn.Embedding)는 각 토큰 ID를 행 번호로 삼아, 미리 학습된 실수 가중치 행렬에서 해당 행의 벡터를 직접 복사해 오는 룩업 테이블(Lookup Table) 방식으로 동작한다.
복잡한 수학적 연산 과정 없이, 파이썬의 map[token_id]처럼 메모리 상에서 해당 인덱스의 실수 행을 직접 조회하여 즉각 반환하는 구조이므로 극도로 빠르고 효율적이다.
코드 예시
import torch
import torch.nn as nn

token_ids = torch.tensor([5, 1523, 892, 6]) # [CLS] 고양이가 좋아요 [SEP] 에 해당하는 토큰 ID들

embedding = nn.Embedding(30000, 768) # 30,000개 사전 크기와 768차원 임베딩 레이어 선언
vectors = embedding(token_ids) # 인덱스 조회를 통해 밀집 벡터들을 즉각 반환 (Lookup)
# vectors.shape ➡️ torch.Size([4, 768]) (토큰 수 × 임베딩 차원)

💡 참고: 위 시각화의 밀집 벡터 수치들은 모델을 처음 생성한 초기 상태(난수)를 나타낸다. 따라서 아직은 단어의 어떠한 의미적 관계도 담겨 있지 않으며, 모델을 데이터셋으로 학습시켜 나감에 따라 가중치 행렬의 실수값들이 점차 최적화되어 진짜 단어 의미를 대변하게 된다.
💡 BERT란 무엇인가?
BERT는 구글이 개발한 양방향 언어 이해 인공지능 모델이다. 타겟 단어 기준 앞뒤(양방향) 문맥을 동시에 파악하여 단어의 정확한 의미와 단어 간의 유기적 관계를 학습한다.
📝 핵심 학습 방식
문장 속 단어 일부를 [MASK](빈칸)로 가려두고, 주변 문맥을 읽어 "빈칸에 들어갈 올바른 단어 조각이 무엇인지" 맞추며 인간 언어의 원리를 학습(독학)한다.
✂️ WordPiece와의 시너지
모든 단어를 통째로 가리면 맞추기 어렵지만, 서브워드 조각으로 쪼개어 가리면 앞뒤 접사나 어근의 힌트를 바탕으로 모르는 단어도 영리하게 예측해 낼 수 있다.
🤖 BERT 학습 — MLM (Masked Language Modeling)
BERT는 입력 토큰 시퀀스에서 일부를 [MASK]로 가리고, 주변 문맥을 참고하여 원래 토큰을 맞추는 방식으로 언어 표현을 학습한다.
① 원본 문장 → 토크나이저 변환 과정
"고양이가 생선을 먹어요"
(아직 "생선을", "먹어요"가 단어로 등록되지 않고 "생" + "##선" + "##을", "먹" + "##어" + "##요"로 서브워드 분리 토큰화된 상태)
고양이가 생 ##선 ##을 먹 ##어 ##요

📈 BERT 예측 & 가중치 업데이트
BERT의 문제 해결 과정
📥 입력 : [고양이가] [MASK] [##선] [##을] [먹] [##어] [##요]
🧠 "고양이가"의 다음 토큰이며, "##선"과 함께 붙어 다니고, "먹어요"와 긴밀히 연관되어 있음을 문맥적으로 추론한다.
    → 그 후 vocab 30,000개 각각에 대해 확률을 계산(Softmax)한다.
ID 1 : "고" → 0.001% ID 2 : "양" → 0.003% … ID 8821 : "생" → 85.2% ✅ ID 8822 : "선" → 2.1%
✅ 정답을 맞혔을 때
예측값 8821('생')이 정답 8821('생')과 일치하므로 Loss가 낮다.
→ 100% 확신의 확률이 아니었으므로 미세하게 가중치를 조정하여, 다음 번에 더 높은 확신을 갖고 예측할 수 있도록 학습한다.
❌ 오답을 냈을 때
예측값 4532('선')이 정답 8821('생')과 다르므로 Loss가 매우 높다.
→ 역전파(Backpropagation) 과정을 통해 관련 가중치를 대폭 업데이트한다.
→ 이로써 "고양이가 다음 위치에 오고 ##선과 결합할 때 '생'이 올 확률이 높다"라는 사실을 강력하게 학습한다.
