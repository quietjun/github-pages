BertWordPieceTokenizer & Embedding

Hugging Face의 tokenizers 라이브러리를 활용하여 단어를 의미 단위의 서브워드로 분리하고, 사전을 구축하여 밀집 벡터로 변환하는 전체 파이프라인을 분석한다.

1. 서브워드 토큰화 개요 & 접두사(##) 메커니즘

서브워드 토큰화(Subword Tokenization)는 단어(Word)보다 작고 문자(Character)보다 큰 ‘의미 있는 조각(Subword)’ 단위로 단어를 분리하여 사전을 구축하는 기법이다. 단어 단위의 어휘 폭발 문제와 문자 단위의 의미 유실 문제를 동시에 해결하는 현대 자연어 처리(NLP)의 표준 방식이다.

개념 정의
서브워드 토큰화의 필요성

• 자연어의 한계: 새로운 조어, 복합어, 파생어가 무한히 생성되어 모든 단어를 사전에 개별 등록하기 어렵다.

• 서브워드 해결: 자주 쓰이는 단어는 그대로 유지하고, 드문 단어는 의미 있는 서브워드로 쪼개어 제한된 사전 크기로 무한한 단어 조합을 유연하게 표현한다.

규칙 표기
연속 서브워드 접두사(##)의 역할

단어의 첫 번째 서브워드를 제외한 나머지 연속된 조각들에는 ## 접두사를 부착하여 단어 시작 위치를 구분한다.

playing ➔ play + ##ing
|
고양이가 ➔ 고양이 + ##가
기존 토큰화 방식 대비 3대 효과 비교
구분 상세 메커니즘 및 극복 효과
단어 단위의 한계 극복 파생어나 조사 결합형(공부, 공부하다, 공부는 등)을 사전에 개별 등록할 필요가 없어 어휘 사전(Vocab) 크기가 폭발적으로 팽창하는 현상을 방지한다.
문자 단위의 한계 극복 단어를 낱글자로만 완전히 해체하여 의미를 유실하거나 문맥 이해에 필요한 토큰 시퀀스 길이가 과도하게 늘어나는 연산 병목을 방지한다.
미등록 단어(OOV) 해결 사전에 없는 낯선 단어(Out-Of-Vocabulary, OOV)도 자주 쓰이는 서브워드(어근, 접사 등) 블록들의 조합으로 분해하여 형태적 의미를 올바르게 유추한다.

2. BertWordPieceTokenizer 훈련 파라미터

Hugging Face의 BertWordPieceTokenizer는 말뭉치(Corpus)로부터 통계적 빈도 기반의 서브워드 사전을 학습한다. 주요 학습 메서드 시그니처와 매개변수는 다음과 같다.

Method Signature: tokenizer.train()
tokenizer.train(
    files: Union[str, List[str]],
    vocab_size: int = 30000,
    min_frequency: int = 2,
    special_tokens: List[str] = ["[PAD]", "[UNK]", "[CLS]", "[SEP]", "[MASK]"],
    limit_alphabet: int = 1000,
    initial_alphabet: List[str] = [],
    wordpiece_prefix: str = "##"
)
vocab_size default: 30,000

최종 생성될 서브워드 사전의 총 단어 수 상한선이다. 빈도 기반 병합을 반복하다가 이 크기에 도달하면 학습을 종료한다.

  • 너무 작을 때: 병합이 조기 종료되어 단편적인 문자 토큰이 많아지고 시퀀스 길이가 길어짐.
  • 너무 클 때: 희귀 단어까지 사전에 포함되어 메모리 및 임베딩 파라미터 낭비 발생.
  • BERT 기준: 영어는 30,000개가 최적이며, 형태소가 발달한 한국어는 더 큰 크기를 권장.
min_frequency default: 2

인접한 서브워드 쌍(Pair)을 하나로 병합하기 위해 필요한 말뭉치 내 최소 등장 횟수 조건이다.

  • 예쁘 + ##ㅂ니다가 1회만 등장하면 병합하지 않고 분리 유지.
  • 고양이 + ##가가 2회 이상 등장하면 고양이가로 병합하여 사전에 등록.
  • 기본 문자(Base Alphabet) 예외: 1회만 등장한 단일 글자는 무조건 사전에 보존.
special_tokens 5종 표준

모델 구조 및 제어에 필요한 특수 목적 토큰 목록이다. 사전의 가장 앞선 고정 인덱스에 할당된다.

  • [PAD]: 배치 연산 시 문장 길이를 맞추기 위한 채움 토큰.
  • [UNK]: 사전에 없는 미등록 어휘(Out-Of-Vocabulary) 대체 토큰.
  • [CLS]: 문장 시작 표시 및 분류(Classification)용 문맥 집약 토큰.
  • [SEP]: 문장의 끝 및 두 문장 간의 경계 구분자 토큰.
  • [MASK]: 마스크 언어 모델(MLM) 학습 시 가려진 빈칸 토큰.
기타 문자 제어 파라미터 Alphabet & Prefix
  • limit_alphabet (default: 1,000): 초기에 등록될 개별 낱글자의 최대 상한선. 빈도가 매우 낮은 희귀 문자는 제외되어 추론 시 [UNK]로 처리.
  • initial_alphabet: 말뭉치 등장 여부와 무관하게 사전에 강제로 사전 등록해 둘 문자 집합.
  • wordpiece_prefix (default: '##'): 단어의 첫 조각이 아닌 후속 연속 서브워드임을 나타내는 접두사 표식.

3. Vocab 구축 5단계 파이프라인 & 스페셜 토큰

WordPiece 알고리즘은 말뭉치를 분석하여 스페셜 토큰 등록부터 기본 문자 등록, 빈도 쌍 병합, 고차 서브워드 확장, 형태소 분리 최적화에 이르는 5단계를 거쳐 사전을 완성한다.

학습용 말뭉치(Corpus) 데이터 예시
"고양이가 좋아요" 2회 등장
"강아지가 귀여워요" 2회 등장
"앵무새를 봤어요" 1회 등장
Step 1
스페셜 토큰 최우선 고정 등록

빈도와 관계없이 고정된 인덱스(ID 0~4)로 사전에 가장 먼저 추가한다.

[PAD] (ID 0) [UNK] (ID 1) [CLS] (ID 2) [SEP] (ID 3) [MASK] (ID 4)
Step 2
말뭉치 내 모든 개별 문자(Base Alphabet) 등록

학습 데이터에 등장한 모든 낱글자를 기본 어휘로 추가한다. min_frequency 조건과 무관하게 1회만 등장해도 사전에 등록된다.

고양이 강아지 앵무새 좋아요 …
Step 3
인접 문자 쌍 빈도 계산 및 병합

단어를 문자 단위로 쪼갠 후(첫 글자 외에는 ## 부착), 인접한 쌍의 등장 빈도가 min_frequency(2회) 이상인 쌍만 병합한다.

고##양 2회 등장 ✓ ➔ 고양으로 병합하여 사전에 추가
강##아 2회 등장 ✓ ➔ 강아로 병합하여 사전에 추가
앵##무 1회 등장 ✗ ➔ 빈도 기준 미달로 병합하지 않고 앵, ##무로 분리 유지
Step 4
더 긴 서브워드로의 점진적 확장 병합

이미 병합된 서브워드 단위끼리 결합 빈도를 재계산하여 더 긴 단위로 병합하며, vocab_size에 도달할 때까지 반복한다.

1. 고양 + ##이 ➔ 고양이 (2회 ✓)
2. 강아 + ##지 ➔ 강아지 (2회 ✓)
3. 고양이 + ##가 ➔ 고양이가 (2회 ✓)
Step 5
형태소적 특성 고려 — 어근과 조사의 분리 최적화

단어를 무조건 통째로 병합하기보다 형태소 단위로 분리하는 것이 어휘의 재사용성을 극대화한다.

❌ 통합 토큰화의 한계 (Vocab 폭발)
학교에 학교로 학교는

모든 조사 결합형을 개별 토큰으로 등록해야 하므로 사전 크기가 기하급수적으로 증가하고 데이터 희소성(Sparsity)이 발생한다.

✅ 분리 토큰화의 이점 (재사용성 극대화)
학교 집 + ##에

어근과 조사를 분리하여 적은 수의 서브워드 토큰만으로도 수많은 문장 변이에 효과적으로 대응할 수 있다.

스페셜 토큰 실전 사용 예시
[CLS] / [SEP] — 문장 구조
[CLS] 강아지가 귀여워요 [SEP]

[CLS]는 문장 시작 및 분류용 표현 집약, [SEP]는 문장의 끝 및 구분자로 동작한다.

[UNK] — 미등록 문자 대체
[UNK] [UNK] [UNK] ("我爱你")

기본 사전에 없는 한자, 이모지, 희귀 외래어는 추론 시 안전하게 [UNK]로 변환된다.

[PAD] — 배치 길이 통일
토끼 [PAD] (길이 2 통일)

배치 묶음 연산 시 짧은 문장 뒤에 패딩을 채우며, Attention Mask로 연산에서 제외한다.

4. 인코딩 및 nn.Embedding 룩업 테이블

토크나이저는 텍스트를 정수 인덱스(Token ID)로 변환하고, 파이토치의 nn.Embedding 레이어는 이 ID를 고정된 차원의 학습 가능한 실수 밀집 벡터(Dense Vector)로 변환(Mapping)한다.

텍스트에서 임베딩 벡터로의 변환 흐름
왜 이렇게 하나요? — 정수 ID 대신 실수 밀집 벡터(Embedding)를 사용하는 이유

컴퓨터는 단순 번호(ID)만으로는 단어의 의미적 거리나 관계를 계산할 수 없으므로, 모든 단어를 의미 공간 상의 실수 벡터로 변환해야 한다.

❌ 단순 정수 인덱스 ID의 한계
고양이가 ➔ [ID 1523]
  • 정수 인덱스는 단순한 고유 식별자 번호에 불과하다.
  • ID 1523과 1524 사이에는 어떠한 언어적, 의미적 유사도나 기하학적 거리 개념도 성립하지 않는다.
✅ nn.Embedding 밀집 벡터 변환의 이점
고양이가 ➔ [0.12, -0.34, 0.88, … 768차원]
  • 차원 축소: 원-핫 인코딩(3만 차원) 대비 고정된 저차원(768차원)으로 메모리를 대폭 절약한다.
  • 유의미한 유사도 학습: 단어의 의미적 유사성이 연속 벡터 공간 상의 코사인 거리로 완벽히 표현된다.
nn.Embedding 룩업 테이블(Lookup Table) 매핑 원리

임베딩 레이어는 복잡한 행렬곱 대신 파이썬의 딕셔너리(map[id])처럼 메모리 상에서 해당 행의 가중치 벡터를 즉시 인덱싱하여 복사해 온다.

📖 1. Vocab (단어 ➔ ID 매핑)
[CLS] ID 5
고양이가 ID 1523
좋아요 ID 892
[SEP] ID 6
➔
행 룩업
(Lookup)
🧱 2. Embedding Table (ID ➔ 768차원 실수 벡터)
ID 5 [0.03, 0.71, -0.15, …]
ID 1523 [0.12, -0.34, 0.88, …]
ID 892 [0.88, 0.11, -0.42, …]
ID 6 [0.55, -0.12, 0.04, …] 
import torch
import torch.nn as nn

token_ids = torch.tensor([5, 1523, 892, 6])     # [CLS] 고양이가 좋아요 [SEP]
embedding = nn.Embedding(30000, 768)            # 30,000개 사전, 768차원 밀집 벡터 레이어
vectors = embedding(token_ids)                  # 룩업 테이블에서 즉각 실수 벡터 행 추출
# vectors.shape ➔ torch.Size([4, 768])

5. BERT 사전학습 연계 — MLM과 가중치 갱신

BERT는 입력 토큰 시퀀스의 일부를 [MASK]로 가린 후, 양방향 문맥을 참고하여 원래 토큰을 맞추는 마스크 언어 모델(Masked Language Modeling, MLM) 방식으로 사전학습을 수행한다.

MLM 2단계 프로세스: 토큰화 및 15% 랜덤 마스킹
① 원본 문장 ➔ 서브워드 토큰화
"고양이가 생선을 먹어요"
고양이가 생 ##선 ##을 먹 ##어 ##요
Token IDs: [1523, 8821, 4532, 221, 9012, 334, 219]
② 랜덤 15% 마스킹 ➔ '생'(ID 8821) 토큰을 [MASK]로 대체
고양이가 [MASK] ##선 ##을 먹 ##어 ##요
입력 Token IDs : [1523, 4, 4532, 221, 9012, 334, 219] ([MASK] = ID 4)
정답 Labels    : [-100, 8821, -100, -100, -100, -100, -100]
※ -100은 손실 함수(CrossEntropyLoss) 계산에서 무시되는 인덱스이며, 오직 마스킹된 위치(8821)에 대해서만 오차를 계산한다.
Softmax 확률 예측 및 역전파 가중치 업데이트
BERT의 문맥 추론 과정

입력: [고양이가] [MASK] [##선] [##을] [먹] [##어] [##요] ➔ "고양이가" 뒤에 오고 "##선"과 결합하며 "먹어요"의 목적어라는 양방향 문맥을 분석하여 전체 30,000개 Vocab에 대한 Softmax 확률을 도출한다.

ID 1 ("고") : 0.001% ID 2 ("양") : 0.003% … ID 8821 ("생") : 85.2% ✅ (최고 확률 예측) ID 8822 ("선") : 2.1%
✅ 정답을 맞혔을 때 (Loss 낮음)

예측값 8821('생')이 정답과 일치하므로 손실(Loss)이 낮다. 100% 확신이 아니었던 차이만큼 가중치를 미세 조정하여 다음 번에 더 높은 확신도로 예측하도록 최적화한다.

❌ 오답을 냈을 때 (Loss 높음)

예측값이 정답과 다를 경우 손실이 매우 높게 발생하며, 역전파(Backpropagation)를 통해 관련 가중치를 대폭 업데이트하여 해당 문맥 패턴을 강력하게 학습한다.
