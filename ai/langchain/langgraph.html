LangGraph 에이전트 아키텍처 및 구현 가이드

LangGraph는 LLM에게 상태(State)와 제어 흐름(Graph)을 부여하여 순환 루프(Cycle)와 복잡한 분기 조건을 자율적으로 수행하도록 지원하는 에이전트 설계 프레임워크이다.

Agent Pipeline = StateGraph(State) → Node(Action) + Edge(Routing)

1. 핵심 구성요소

LangGraph는 세 가지 기본 추상화 요소를 기반으로 워크플로우를 구성한다.

📋 State

공유 메모장 · 공용 데이터 저장소

  • 모든 노드가 공유하는 전역 데이터 저장소
  • 이전 작업 히스토리 기록 및 에러 복구 기준점 제공
  • 중간 결과를 누적하여 최종 판단 근거로 활용

⚙️ Node

전문가 단위 작업자 · 실행 함수

  • 특정 업무만 수행하는 단위 함수
  • State 입력 → 비즈니스 로직 처리 → State 업데이트
  • 검색, 요약, 번역, 평가 단위별 격리
  • Python 함수 또는 LLM 호출 인터페이스 매핑

🔀 Edge

업무 지시서 · 제어 전이 통로

  • 노드 간 실행 전이 경로 명시
  • 일반 엣지: 항상 동일한 경로로 확정적 이동
  • 조건부 엣지: 상태 값에 따라 동적 분기
  • 품질 저하 시 재검색 루프, 정상 완료 시 END 전이

2. Self-Correcting RAG 워크플로우

LangGraph 기반 자율 보정형(Self-Correcting) RAG 파이프라인의 상태 전이 흐름이다. 각 노드를 클릭하면 하단 설명창에 세부 동작 원리가 표시된다.

💡 각 노드를 클릭하면 단계별 상세 설명이 표시된다.

3. 핵심 차별 기능

🔁

사이클(Cycle) 허용

정답을 찾을 때까지 반복 실행을 지원하여 자기수정(Self-Correcting) AI를 구현한다.

💾

체크포인트

작업 중간 상태를 저장하여 서버 장애 발생 시 마지막 저장점부터 즉시 재개한다.

🧑‍💼

Human-in-the-loop

중요 행동 전 실행을 일시 정지하고 사람의 승인 후 다음 노드로 진행한다.

4. 파이프라인 아키텍처 비교 (LCEL vs LangGraph)

기존 단방향 파이프라인(LCEL)과 순환 네트워크 구조(LangGraph)의 동작 차이를 비교한다.

LCEL · 기존 방식

일방통행 레시피 → 순서대로만 실행, 되돌아가기 불가

LangGraph · 새로운 방식

사거리·회전교차로형 도로망 → 조건 분기, 루프, 유턴 모두 지원

비교 항목 LCEL (기존 방식) LangGraph (새로운 방식)
구조 형태 일방통행 선형 파이프라인 (직선 구조) 사거리 및 회전교차로형 그래프 네트워크
순환 및 유턴 불가 (순차 실행 한정) 자유로운 사이클(Cycle) 및 루프 지원
조건 분기 단순/제한적 분기 처리 조건부 엣지(Conditional Edge) 기반 동적 분기
상태 제어 체인 간 데이터 암묵적 전달 Shared State 기반 명시적 데이터 입출력 관리
주요 타깃 단순 파이프라인 최적화 복잡한 자율 에이전트 로직 구현

5. 기술 스택 선택 기준

업무 복잡도와 피드백 루프 필요성에 따라 적절한 도구를 선택한다.

LCEL 권장 시나리오 LangGraph 권장 시나리오
  • 단순 번역, 텍스트 요약 등 1회성 작업
  • 입출력이 명확하게 정의된 선형 파이프라인
  • 빠른 프로토타이핑이 필요한 환경
  • 분기 및 반복 루프가 불필요한 단순 체인
  • 다수 문헌 종합 비판적 분석 보고서 작성
  • 코드 생성 → 실행 에러 수정 → 재실행 루프
  • 환각 검증 및 재검색이 결합된 다단계 RAG 파이프라인
  • 사람의 최종 승인이 필요한 자동화 워크플로우

6. Python 실무 구현 예제

RAGState 기반으로 검색(Retrieve)과 생성(Generate) 노드를 연결하는 2노드 순차 에이전트 파이프라인 구현 코드이다.

# 1. State 타입 정의 (공유 메모리)
from typing import TypedDict
from langchain_core.prompts import ChatPromptTemplate
from langgraph.graph import StateGraph, START, END

class RAGState(TypedDict):
    question: str
    context: str
    answer: str

# 2. Retrieve 노드 정의 (유사 문서 검색)
def retrieve(state: RAGState) -> dict:
    question = state["question"]
    
    # 청킹된 Vector Store에서 문장 검색 후 포맷팅
    docs = retriever_chunked.invoke(question)
    context = "\n\n".join([doc.page_content for doc in docs])
    return {"context": context}

# 3. Generate 노드 정의 (답변 생성)
def generate(state: RAGState) -> dict:
    question = state["question"]
    context = state["context"]
    
    rag_prompt = ChatPromptTemplate.from_messages([
        ("system", "당신은 Yes24 상담원입니다. 검색된 자료에만 기반하여 답하세요:\n\n{context}"),
        ("human", "{question}")
    ])
    
    messages = rag_prompt.format_messages(context=context, question=question)
    response = llm.invoke(messages)
    return {"answer": response.content}

# 4. StateGraph 워크플로우 구성 및 컴파일
workflow = StateGraph(RAGState)

# 노드 등록
workflow.add_node("retrieve", retrieve)
workflow.add_node("generate", generate)

# 엣지 연결 (순차 실행 흐름 정의)
workflow.add_edge(START, "retrieve")
workflow.add_edge("retrieve", "generate")
workflow.add_edge("generate", END)

# 그래프 컴파일 및 호출
rag_graph = workflow.compile()
result = rag_graph.invoke({"question": "Yes24에서 총알배송이 뭔가요?"})
print(result["answer"])

핵심 요약

  • LangGraph는 단방향 LCEL을 넘어 상태 보존과 순환 루프 제어를 지원하는 에이전트 프레임워크이다.
  • State(공유 데이터), Node(실행 함수), Edge(전이 통로)의 3요소로 그래프를 설계한다.
  • 모호성 검사, 품질 평가, 환각 검증을 피드백 루프로 자율 보정하는 Self-Correcting RAG를 구축한다.
  • 체크포인트를 통한 상태 영속화 및 Human-in-the-loop 승인 체계를 제공하여 엔터프라이즈 신뢰성을 보장한다.
