RETRIEVAL-AUGMENTED GENERATION

외부 데이터와의 실시간 협업으로
환각(Hallucination)을 방지하는 RAG

RAG(검색 증강 생성) : LLM이 학습하지 못한 최신 정보나 사내 문서 등 외부 데이터를 실시간으로 검색 ➡️ 그 내용을 프롬프트에 주입하여 신뢰성 높고 검증 가능한 정확한 답변을 유도하는 기법

01

등장 배경 : 왜 RAG가 대세인가?

사전 학습(Pre-training) 기반 LLM이 가진 고질적인 네 가지 문제를 우회적으로 해결

지식 파편화 & 지식 컷오프
모델은 학습이 끝난 시점까지만 기억함 → 매일 변경되는 최신 뉴스나 실시간 트렌드 질문에 빈 답변 생성
환각 현상 (Hallucination)
모르는 질문도 그럴싸한 거짓말로 그럴듯하게 작문해 냄 → 신뢰도가 생명인 비즈니스 서비스에 치명적
비공개 데이터 접근 한계
보안이 중요한 사내 인사 문서, 규정, 계약서 등은 인터넷에 노출되어 있지 않아 학습 모델에 포함 불가
재학습 비용의 한계
지식이 업데이트될 때마다 수십 억 원이 드는 모델 재학습(Fine-tuning)을 매일 돌리는 것은 불가능
→ RAG : 모델 두뇌의 지식을 업데이트하는 대신, 똑똑한 도서관(외부 Vector DB)을 지어주는 방식
02

RAG 전체 작동 파이프라인

데이터 준비(ETL 파이프라인), 검색(Retrieval), 답변 생성(Generation)의 흐름

실선 : API 및 프로세스 처리 흐름 · 점선 : 데이터 검색(Retrieval) 및 반환 통로
03

RAG 주요 3단계 상세 프로세스

각 파이프라인 단계에서 수행되는 기술적 역할

STEP 1

ETL (데이터 준비)

  • 추출 (Extract / Reader): PDF, 웹페이지 등 소스로부터 데이터를 읽어와 정형화된 문서(Document) 객체로 가져온다.
  • 변환 (Transform / Splitter): 추출된 문서를 LLM이 읽기 적합하도록 작은 조각인 텍스트 청크(Chunk)로 쪼갠다.
  • 적재 (Load / Writer): 쪼개진 청크들을 임베딩 모델을 통해 벡터로 변환(Embedding)함과 동시에 Vector DB에 물리적으로 저장(Write)한다.
STEP 2

Retrieval (검색)

  • 쿼리 벡터 변환: 사용자가 던진 한국어 질문 역시 문서와 똑같은 임베딩 모델로 벡터화한다.
  • 유사도 연산: 질문 벡터와 Vector DB 안에 저장된 청크 벡터 간의 거리(코사인 유사도 등)를 연산한다.
  • 탑-K 추출: 연산 결과 유사도가 가장 높은 상위 K개(예: 3개)의 청크 문서를 가져온다.
STEP 3

Generation (답변 생성)

  • 컨텍스트 주입: 가져온 상위 문서 정보들을 프롬프트의 `{context}` 빈칸에 밀어 넣는다.
  • 생성 요청: "주어진 [context] 정보에만 기반하여 질문에 답해줘"라고 LLM 지시 사항을 함께 발송한다.
  • 답변 반환: LLM은 상상의 지식이 아닌 오직 전송받은 사실에만 입각하여 정제된 최종 답변을 만든다.
04

RAG 성능의 핵심 : 청킹(Chunking) 전략

긴 문서를 검색 정확도와 토큰 비용에 최적화된 크기로 쪼개어 문맥 유실을 극복하는 전략

토큰 한계 극복 (Token Limits)
대형 언어 모델(LLM)이 한 번에 읽을 수 있는 입력 토큰 크기는 정해져 있으므로, 거대한 원본 문서를 적절한 크기로 분할하여 전달해야 합니다.
검색 정확도 향상 (Retrieval Accuracy)
문서 단위가 너무 크면 중요 정보가 묻히는 희석 현상이 발생합니다. 의미 단위로 쪼개어 질문과 깊이 연관된 청크만 선별합니다.
문맥 연결성 확보 (Overlap)
기계적으로 자르면 문장 중간에 정보가 유실될 위험이 큽니다. 청크 사이에 중복 구간(Overlap)을 두어 정보의 연속성을 유지합니다.
비용 및 대기시간 최소화 (Cost & Latency)
불필요하게 많은 텍스트를 LLM에 전송하지 않으므로 불필요한 토큰 사용량을 최소화하고 모델의 빠른 추론 속도를 유도합니다.
⚡ INTERACTIVE CHUNKING SIMULATOR

텍스트를 입력하고 슬라이더를 조절하여 Chunk Size(청크 크기)와 Chunk Overlap(중복 범위)에 따라 문서가 어떻게 분할되는지 실시간으로 테스트해 본다. 주황색 음영은 이전 청크와 겹치는 중복 영역이다.

상용 AI 시스템 구현 시, 다루는 원본 데이터의 특성에 맞추어 청킹의 크기와 중복 범위를 튜닝하는 작업이 RAG 성공의 핵심입니다.

⚠️ 기계적 청킹(Character-based)의 근본적 한계와 극복 기술

단순 글자 수나 개행 문자 단위로 문서를 기계적으로 분할할 경우, 중요 문장이나 인과적 관계가 있는 맥락(Context)이 청크 간 경계선에서 강제 단절되는 심각한 한계가 존재한다. 상용 RAG 시스템에서는 이를 보완하기 위해 다음과 같은 고급 청킹·검색 고도화 전략을 적용한다.

1. Semantic Chunking (의미론적 청킹)
기계적인 숫자 단위 분할을 지양하고, 각 문장 간의 임베딩 벡터 유사도를 연산하여 유사성이 크게 급변(유사도 지수가 급강하)하는 경계 지점을 감지하여 논리적으로 단락을 구분하는 청킹 기법이다.
2. Parent-Child / Sentence-Window Retriever (상하관계 및 윈도우 검색)
유사도 매칭율을 올리기 위해 벡터 스토어 DB에는 아주 잘고 촘촘하게 쪼갠 하위 청크(Child)로 색인해 검색하고, 검색 완료 후 LLM에 주입할 때는 해당 자식 청크가 원래 소속되어 있던 충분히 넓은 본문 영역의 상위 컨텍스트(Parent)를 프롬프트에 얹어 넘겨줌으로써 문맥 단절을 완벽하게 예방하는 실무 핵심 기법이다.
3. Contextual Retrieval (맥락적 청킹 보강)
개별 청크가 조각날 때 문서 전체의 대주제나 전체 요약본(Context)을 상실하여 검색 품질이 저하되는 현상을 개선한다. 문서 전체에 대한 요약문을 생성한 뒤 모든 청크의 머리글에 접두사(Prefix)로 자동 결합하여 개별 청크마다 고유의 거시적 맥락을 주입하는 최신 검색 강화 아키텍처이다.
05

LangChain & Chroma 실무 구현 가이드

실제 Python 코드로 구현하는 RAG 파이프라인의 핵심 5단계 흐름과 코드 스니펫

🛠️ RAG 파이프라인 5단계 구현 코드

# 1. 문서 로드 (Document Load)
from langchain_community.document_loaders import PyMuPDFLoader
loader = PyMuPDFLoader("data/service_policy.pdf")
documents = loader.load()

# 2. 텍스트 분할 및 청킹 (Text Splitting / Transform)
from langchain_text_splitters import RecursiveCharacterTextSplitter
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,
    chunk_overlap=50,
    length_function=len
)
chunked_docs = text_splitter.split_documents(documents)

# 3. 임베딩 및 Vector DB 적재 (Embedding & Load)
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(
    documents=chunked_docs,
    embedding=embeddings,
    persist_directory="./chroma_db",
    collection_name="policy_docs"
)

# 4. 검색기 생성 (Retrieval)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 5. 질문 답변 체인 구축 & 실행 (Generation / LCEL)
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "참고자료에만 기반하여 고객의 질문에 답하세요:\n\n{context}"),
    ("human", "{question}")
])

chain = prompt | llm | StrOutputParser()

# RAG 파이프라인 구동
query = "Yes24에서 배송지연 보상 조건은 어떻게 되나요?"
retrieved_docs = retriever.invoke(query)
context_text = "\n\n".join([doc.page_content for doc in retrieved_docs])

response = chain.invoke({"context": context_text, "question": query})
print("최종 응답:", response)
