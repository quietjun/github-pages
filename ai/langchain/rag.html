RAG(검색 증강 생성) 기술 소개 외부 데이터와의 실시간 협업으로 환각(Hallucination)을 방지하는 RAG 아키텍처

LLM이 사전 학습하지 못한 최신 정보나 사내 보안 문서 등 외부 지식을 실시간으로 검색하여 프롬프트에 주입함으로써, 신뢰성 높고 검증 가능한 정확한 답변을 생성 유도하는 RAG(Retrieval-Augmented Generation) 기법이다.

"RAG 시스템은 LLM의 한계인 지식 컷오프와 환각 현상을 모델 재학습 없이 외부 Vector DB 기반 검색으로 극복하는 실무 핵심 아키텍처이다."

1. 등장 배경 : 왜 RAG가 대세인가?

사전 학습(Pre-training) 기반 LLM이 가진 4가지 구조적 한계점을 효과적으로 우회 극복한다.

📅

1. 지식 파편화 & 지식 컷오프

학습 시점 이후의 최신 뉴스나 실시간 트렌드 질문에 대해 모른다고 답하거나 잘못된 과거 정보 반환함

🌀

2. 환각 현상 (Hallucination)

모르는 지식 질문에 대해서도 정답인 것처럼 그럴듯한 거짓 문장을 작문하여 금융/법률/보안 서비스에 치명적 위험 초래함

🔒

3. 비공개 데이터 접근 한계

사내 인사 문서, 규정, 계약서 등 공개되지 않은 비공개 사내 보안 지식은 외부 오픈소스 학습 모델에 포함 불가함

💸

4. 재학습 비용의 한계

새로운 지식이 추가될 때마다 수십 억 원이 소요되는 파인튜닝(Fine-tuning)을 매일 재학습 시키는 것은 불가능함

💡 RAG 아키텍처 솔루션: 모델 두뇌의 파라미터 지식을 직접 변경하는 대신, 똑똑한 외부 도서관(Vector DB)을 지어주고 실시간으로 책을 찾아주는 방식을 취한다.

2. RAG 전체 작동 파이프라인

데이터 준비(ETL 파이프라인), 유사도 검색(Retrieval), 프롬프트 주입 및 답변 생성(Generation)의 전체 시스템 구성도이다.

3. RAG 주요 3단계 상세 프로세스

각 파이프라인 단계별 핵심 기술적 구동 방식이다.

STEP 1

ETL (데이터 준비)

  • 추출 (Extract): PDF, 웹페이지 등에서 원본 데이터를 정형화된 Document 객체로 로드함
  • 변환 (Transform): 문서를 LLM이 처리하기 적합한 작은 단락 조각(Chunk)으로 쪼갬
  • 적재 (Load): 청크를 임베딩 모델을 통해 벡터화하여 Vector DB에 최종 저장을 완료함
STEP 2

Retrieval (검색)

  • 쿼리 벡터 변환: 사용자 질문을 동일한 임베딩 모델을 통해 수치 벡터로 변환함
  • 유사도 연산: 질문 벡터와 Vector DB 내 청크 벡터 간 거리(코사인 유사도 등)를 측정함
  • Top-K 추출: 유사도가 가장 높은 상위 K개(예: 3개)의 관련 청크 문서를 즉시 반환함
STEP 3

Generation (답변 생성)

  • 컨텍스트 주입: 가져온 상위 문서를 프롬프트 내 {context} 위치에 밀어 넣음
  • 생성 요청: "제공된 맥락 정보에만 기반하여 답변하라"는 지시를 LLM으로 전송함
  • 답변 반환: LLM이 전송받은 문맥 사실에만 입각하여 정제된 최종 응답을 완성함

4. RAG 성능의 핵심 : 청킹(Chunking) 전략

긴 문서를 검색 정확도와 토큰 비용에 최적화된 크기로 쪼개어 문맥 유실을 극복하는 4대 필요성 및 실시간 시뮬레이터이다.

1. 토큰 한계 극복 (Token Limits)

LLM이 한 번에 처리 가능한 입력 토큰 크기는 제한되어 있으므로 대용량 문서를 분할 전달함

2. 검색 정확도 향상 (Retrieval Accuracy)

문서 단위가 너무 크면 핵심 정보가 희석되므로 의미 단위 조각으로 질문과 직접 관련된 청크만 선별함

3. 문맥 연결성 확보 (Overlap)

기계적 분할 시 경계선 문장이 잘리는 단절을 방지하기 위해 청크 간 중복 구간(Overlap)을 설정함

4. 비용 및 대기시간 최적화 (Cost & Latency)

불필요한 텍스트 전송을 줄여 API 토큰 소모 비용을 낮추고 LLM의 빠른 응답 속도를 유도함

⚡ INTERACTIVE CHUNKING SIMULATOR

슬라이더를 조절하여 Chunk Size(청크 크기)와 Chunk Overlap(중복 범위) 설정값에 따라 입력 텍스트가 실시간 분할되는 양상을 검증한다. 주황색 뱃지는 이전 청크와 중복되는 영역이다.

📋 문서 도메인 및 성격별 실전 권장 청킹 가이드

문서 유형 권장 Chunk Size 권장 Overlap 비율 최적화 목적
FAQ (단답식) 100 ~ 200자 0% ~ 10% 질문과 답변이 독립된 한 쌍이므로 문맥 중복이 거의 불필요함
사내 규정 / 정책 문서 300 ~ 500자 15% ~ 20% 조건절과 예외 항목이 많아 문맥적 일관성 보존이 극히 중요함
기술 매뉴얼 / 장문 설명 500 ~ 800자 10% ~ 15% 길고 구조화된 기술적 절차와 명세를 풍부한 맥락으로 획득함
계약서 / 법률 조항 200 ~ 300자 20% ~ 25% 단어 하나로 법적 구속력이 갈리므로 매우 촘촘한 탐색이 강제됨

⚠️ 기계적 청킹(Character-based) 한계 극복을 위한 고급 전략

1. Semantic Chunking (의미론적 청킹)

글자 수 기준 분할 대신 문장 간 임베딩 유사도가 급격히 변하는 지점을 감지하여 논리적 단락을 자동 분할함

2. Parent-Child / Sentence-Window Retriever (상하관계 검색)

DB 탐색 시에는 작은 자식 청크(Child)로 색인 검색하고, LLM 전달 시에는 해당 조각이 속한 넓은 상위 본문(Parent)을 주입하여 문맥 단절을 차단함

3. Contextual Retrieval (맥락적 청킹 보강)

문서 전체에 대한 요약문을 생성한 뒤 모든 청크의 머리글에 접두사(Prefix)로 자동 결합하여 거시적 문맥을 개별 청크에 유지시킴

5. LangChain & Chroma 실무 구현 가이드

실제 Python 코드로 구현하는 RAG 파이프라인 5단계 핵심 구성 방식이다.

💻 Python RAG 파이프라인 5단계 완전 파이프라인 소스코드

# 1. 문서 로드 (Document Load / Extract)
from langchain_community.document_loaders import PyMuPDFLoader

loader = PyMuPDFLoader("data/service_policy.pdf")
documents = loader.load()

# 2. 텍스트 분할 및 청킹 (Text Splitting / Transform)
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,
    chunk_overlap=50,
    length_function=len
)
chunked_docs = text_splitter.split_documents(documents)

# 3. 임베딩 및 Vector DB 적재 (Embedding & Load)
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(
    documents=chunked_docs,
    embedding=embeddings,
    persist_directory="./chroma_db",
    collection_name="policy_docs"
)

# 4. 검색기 생성 (Retrieval)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 5. 질문 답변 체인 구축 & 실행 (Generation / LCEL)
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "참고자료에만 기반하여 고객의 질문에 답하세요:\n\n{context}"),
    ("user", "{question}")
])

chain = prompt | llm | StrOutputParser()

# RAG 파이프라인 구동
query = "Yes24에서 배송지연 보상 조건은 어떻게 되나요?"
retrieved_docs = retriever.invoke(query)
context_text = "\n\n".join([doc.page_content for doc in retrieved_docs])

response = chain.invoke({"context": context_text, "question": query})
print("최종 응답:", response)

6. 강의 핵심 요약

  • RAG 의의: LLM 파라미터 재학습 없이 외부 Vector DB 검색으로 환각 및 지식 컷오프 극복
  • 핵심 3단계: 데이터 추출/청킹/적재(ETL) ➔ 유사도 검색(Retrieval) ➔ 컨텍스트 주입 생성(Generation)
  • 청킹 전략: 문서 도메인 성격에 따른 Chunk Size & Overlap 튜닝 및 Semantic/Parent-Child 고급 전략
  • LangChain 구현: Loader ➔ Splitter ➔ VectorStore ➔ Retriever ➔ LCEL Chain 5단계 바인딩
