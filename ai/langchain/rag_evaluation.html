Ragas 프레임워크 기반 핵심 4대 지표 분석 및 인터랙티브 평가지표 계산기

Concept

이번 포스트에서는 RAG 시스템을 객관적으로 평가하는 기법에 대해 알아본다.

RAG(Retrieval-Augmented Generation) 시스템을 구축하고 나면 가장 먼저 마주하는 난제는 "이 답변이 정말로 정확하고 안전한가?"에 대한 평가이다. 단순히 사람이 눈으로 확인하는 휴먼 평가는 확장성(Scalability) 측면에서 한계가 뚜렷하며 평가 주관이 개입된다. 이 포스트에서는 LLM을 평가 판정관으로 활용하는 Ragas(Retrieval Augmented Generation Assessment) 프레임워크의 핵심 지표들을 시뮬레이션과 함께 상세히 다룬다.

Ragas Evaluation Quad
RAG 평가의 4대 핵심 축 (Ragas Quad)

기존의 3대 축(Triad)을 넘어, 실제 정답(Ground Truth)을 포함한 4대 핵심 구성요소 간의 유기적 관계를 통해 평가 체계를 수립합니다.

  • Context Precision (맥락 정밀도): 질문 대비 검색된 맥락 정보 중 관련성 높은 정보들이 상위에 위치하는지 평가합니다.
  • Context Recall (맥락 재현율): 실제 정답(Ground Truth)을 도출하기 위해 필요한 지식 정보가 검색된 맥락 안에 빠짐없이 수집되었는지 검증합니다.
  • Faithfulness (충실성/진실성): 생성된 답변이 검색된 맥락(Context)에만 철저히 근거했는지, 모델의 독자적 환각(Hallucination)이 없는지 검증합니다.
  • Answer Relevance (답변 유사성): 생성된 답변이 원래 사용자가 던진 질문의 의도에 적절히 부합하는지 평가합니다.

Ragas Implementation
실습: Ragas 환경 설정 및 파이썬 코드 구현

Ragas 프레임워크를 활용해 평가 프로세스를 코드로 구현하는 방법은 다음과 같다.

의존성 라이브러리 설치: 터미널 창을 열고 아래 패키지를 먼저 설치한다. 
pip install ragas langchain-openai datasets

파이썬 기반 Ragas 평가 스크립트 작성 예시:

# env_setup.py
import os
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall

# 1. API Key 등록
os.environ["OPENAI_API_KEY"] = "your-openai-api-key"

# 2. Ragas 데이터 규격에 맞는 골든 데이터셋 생성
data_samples = {
    'question': ['제주도 8월 평균 기온은 어떤가요?'],
    'contexts': [['제주도의 8월 평균 기온은 26도에서 27도 내외를 기록합니다.']],
    'answer': ['제주도의 8월 평균 기온은 대략 26~27도입니다.'],
    'ground_truth': ['제주도의 8월 평균 기온은 26도에서 27도 내외입니다.']
}
dataset = Dataset.from_dict(data_samples)

# 3. 평가 실행
score = evaluate(
    dataset,
    metrics=[
        faithfulness,
        answer_relevancy,
        context_precision,
        context_recall
    ]
)

# 4. 결과 리포트 출력
df = score.to_pandas()
print(df)

지표별 진단 및 RAG 성능 개선 솔루션
지표 상태 원인 진단 개선 방안 (Action Item)
Context Precision 저하 검색 정보의 관련성 분산 · 리랭커(Reranker) 기법을 도입하여 관련성 높은 청크를 최상단 정렬
· 쿼리 확장(Query Expansion) 및 검색 청크 반환 수(Top-K) 미세 조정
Context Recall 저하 검색 누락 및 핵심 정보 부재 · 임베딩 모델 고도화 수행
· 청크 크기(Chunk Size) 분할 로직 수정
· BM25 하이브리드 검색 기법 도입
Faithfulness 저하 환각 현상 발생 · 시스템 프롬프트(System Prompt)에 근거 제약조건 명시
· LLM의 Temperature 변수를 0에 가깝게 조절
· Context 길이에 따른 압축(Context Compression) 기법 적용
Answer Relevance 저하 초점 이탈 현상 · 프롬프트 내에 출력 포맷 강제 정의
· 사용자의 오리지널 쿼리를 재작성(Query Rewriting)하여 질문의 의도 명확화
