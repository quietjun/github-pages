AI AGENT ARCHITECTURE & DESIGN

목표를 향해 스스로 판단하고
행동하는 AI 에이전트(Agent)

AI 에이전트는 단순한 텍스트 응답 모델을 넘어, 주어진 목표를 달성하기 위해 적절한 도구를 선택(Tool-use)하고, 대화 맥락을 기억(Memory)하며, 사고 및 행동 과정(Plan/ReAct)을 자율적으로 설계하여 문제를 해결하는 시스템이다.

이번 포스트에서는 자율적인 의사결정 루프를 수행하는 AI 에이전트의 4대 핵심 구성요소와 ReAct 패턴의 개념을 이해하고 동작 방식을 시뮬레이션해 본다.
01

AI 에이전트의 4대 핵심 구성요소 (Core Components)

주어진 목표를 완수하기 위해 유기적으로 결합되어 동작하는 에이전트 아키텍처의 네 가지 핵심 기둥이다.

🧠

LLM Brain (의사결정)

자연어 질문 해석 및 단계별 문제 해결을 위한 최종 의사결정 수행.

부재 시: 대화 및 고차원적 의사결정 불가능.
🛠️

Tool Action (행동실행)

외부 DB 조회 및 API 호출을 통해 모델의 지식 한계를 극복하고 조치 대행.

부재 시: 현실적인 시스템 조작 불가 및 할루시네이션 남발.
💾

Memory Context (맥락유지)

대화 이력 및 작업 세션 정보를 저장하여 다단계 수행 흐름 연속성 확보.

부재 시: 대화 내에 이미 제공된 키값이나 맥락 인식 불가능.
🧭

Plan Strategy (사고설계)

자율적 단계별 추론 및 최적의 도구 활용 호출 순서를 설계하고 조율.

부재 시: 중첩 다단계 작업 시 무한 루프 진입 및 제어 오류 발생.
02

도구 바인딩(Tool Binding) 메커니즘 및 코드 대조

파이썬 함수의 독스트링과 타입 선언이 LLM 호출 규격서(JSON Schema)로 매핑되는 실제 예시이다.

1. 도구 이름 (Function Name)

파이썬 함수명(예: get_order_status)이 스키마의 name 필드로 매핑되어 LLM의 직접적인 호출 식별자로 활용됨.

2. 매개변수 타입 힌트

매개변수 타입(예: str, int)이 스키마의 type 정의로 맵핑되어 적합한 자료형 입력을 강제함.

3. 함수 독스트링 (Docstring)

함수 내부의 """설명문"""이 스키마의 description 필드가 되어 LLM이 도구 목적을 판별하는 프롬프트로 기동됨.

4. 인자 설명

독스트링 내의 Args: parameter: 설명 포맷이 인자 설명서로 매핑되어 각 인자의 입력 목적을 LLM에 가이드함.
# @tool 데코레이터 적용 from langchain_core.tools import tool @tool def get_order_status(order_id: str) -> str: """특정 주문의 배송 상태를 조회합니다. Args: order_id: 주문 번호 (예: ORD001) """ return "배송 지연"
{ "name": "get_order_status", "description": "특정 주문의 배송 상태를 조회합니다.", "parameters": { "type": "object", "properties": { "order_id": { "type": "string", "description": "주문 번호 (예: ORD001)" } }, "required": ["order_id"] } }
03

ReAct (Reasoning + Acting) 프레임워크

추론(Thought)과 행동(Action)을 번갈아 수행하며, 관찰(Observation) 결과를 다음 추론에 반영하는 에이전트의 사고 아키텍처이다.

ReAct 아키텍처 : 목표를 달성할 때까지 Thought → Action → Observation 루프를 순환 수행하며 노드가 강조됩니다.
⚡ INTERACTIVE MULTI-SCENARIO SIMULATOR

상황별 시나리오를 선택하여 에이전트의 사고 흐름과 도구 연동을 테스트합니다.

시나리오 선택 (Select Scenario)
시나리오 A: 단순 정책 조회 (1-Step)
"배송 지연 보상 규정이 어떻게 돼?"
시나리오 B: 복합 쿠폰 발급 (Multi-Step)
"ORD001, ORD002 상태 조회 후 지연 건에 보상 쿠폰 발행"
진행 상황: 대기 중
시작 버튼을 누르면 에이전트의 Thought-Action-Observation 루프가 시작된다.
💻 LangGraph 기반 ReAct 에이전트 생성 실전 코드
from langgraph.prebuilt import create_react_agent from langchain_openai import ChatOpenAI # 1. LLM 모델 객체 및 바인딩할 도구 리스트 정의 model = ChatOpenAI(model="gpt-4o") tools = [get_order_status, search_policy] # 2. ReAct 에이전트 생성 (CompiledStateGraph 객체 반환) agent = create_react_agent(model, tools) # 3. 에이전트 실행 (단발성 실행) response = agent.invoke({"messages": [("user", "ORD001 주문 상태를 확인하고 지연 시 조치 정책을 조회해줘.")]})
04

메모리(Memory)를 활용한 대화 맥락(Context) 유지

멀티턴 대화 세션에서 사용자의 이전 발화와 도구 실행 결과를 기억하여 연속성 있는 답변을 생성하는 메모리 아키텍처이다.

💾

MemorySaver (단기 세션)

애플리케이션의 메모리 내에 체크포인트를 저장하여 단일 세션 동안 대화 맥락을 유지함.

특징: 프로세스 재시작 시 메모리 정보 유실.
🗄️

SqliteSaver (디스크 영속)

로컬 SQLite DB 파일에 체크포인트를 저장하여 애플리케이션 재시작 후에도 상태를 보존함.

특징: 영속적인 멀티 세션 히스토리 보존 가능.
🔑

thread_id (세션 구분자)

동일한 대화 스레드를 그룹화하여 고유 세션 간 대화 내역이 섞이지 않도록 격리함.

특징: 설정(config) 키에 세션 ID 매핑 수행.
📌

State Checkpoint (상태 보존)

에이전트의 이전 실행 노드 시점 상태를 스냅샷으로 백업하여 에러 복구 및 롤백을 제어함.

특징: 노드 전파 및 실행의 물리적 시점 저장.
💻 메모리 체크포인터(MemorySaver)를 활용한 대화 맥락 유지 실전 코드
from langgraph.prebuilt import create_react_agent from langchain_openai import ChatOpenAI from langgraph.checkpoint.memory import MemorySaver # 메모리 체크포인터 임포트 # 1. 모델, 도구 목록 및 체크포인터 메모리 세이버 생성 model = ChatOpenAI(model="gpt-4o") tools = [get_order_status, search_policy] memory = MemorySaver() # 메모리 인스턴스 초기화 # 2. 에이전트 빌드 시 checkpointer 매개변수 바인딩 agent = create_react_agent(model, tools, checkpointer=memory) # 3. 고유 세션 ID(thread_id) 설정 config = {"configurable": {"thread_id": "user_session_001"}} # 첫 번째 대화 수행 (주문 상태 요청) agent.invoke( {"messages": [("user", "ORD001 주문 상태를 확인해줘.")]}, config=config ) # 두 번째 대화 수행 (메모리에 기록된 ORD001의 맥락을 이어서 보상 정책 조회) response = agent.invoke( {"messages": [("user", "그럼 지연 건에 대한 보상 조치를 진행해줘.")]}, config=config )
05

Plan - 의사결정 구조 만들기

목표를 달성하기 위해 에이전트가 수행할 작업 단계와 도구 호출 계획을 LLM 스스로 판단하여 결정하는 논리 아키텍처이다.

🧭 ReAct 프레임워크가 곧 Plan의 동작 실체이다

에이전트에게 수동으로 세부 경로를 하드코딩하지 않고, 제공된 도구(Tools) 목록을 활용해 스스로 다음 단계를 계획(Thought)하고 실행(Action)한 후 피드백을 받는 ReAct 순환 아키텍처가 곧 Plan의 구체적인 구현 방식이다.

LangGraph에서는 기성품 헬퍼 함수인 create_react_agent를 사용하는 것만으로도 이 Plan 의사결정 루프가 내장되어 복잡한 멀티 스텝 태스크를 자율적으로 계획해 해결할 수 있다.
