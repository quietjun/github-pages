LLM APPLICATION FRAMEWORK

여러 개의 LLM 호출·도구·데이터를
사슬(Chain)처럼 엮는 프레임워크

LangChain : 프롬프트·모델·검색·메모리·도구를 표준 인터페이스로 연결 → 단발성 LLM 호출을 넘어선 워크플로우 · 에이전트 구성을 지원하는 오픈소스 프레임워크

01

등장 배경 : LLM 단독 호출의 한계

GPT·Claude 등 모델 API를 그냥 호출하는 것만으로는 실제 서비스 구축에 부족 → 아래 4가지 공백 발생

프롬프트 관리 부재
템플릿화 · 버전 관리 · 재사용 구조 없음 → 문자열 하드코딩 반복
외부 데이터 단절
모델은 학습 시점 지식만 보유 → 사내 문서 · DB · 최신 정보 접근 불가
상태(맥락) 미유지
API 호출은 기본적으로 무상태(stateless) → 대화 기록 직접 관리 필요
행동(Action) 불가
계산 · 검색 · API 호출 등 실제 작업 수행 능력 없음 → 텍스트 생성에 국한
→ LangChain : 위 4가지를 각각 Prompt · Retrieval · Memory · Tool 모듈로 표준화
02

핵심 구성요소

입력부터 출력까지, 각 단계를 독립된 컴포넌트로 분리 → 자유롭게 조합(Chain)

실선 : 기본 파이프라인 흐름 · 점선 : 부가 모듈 연결 (Retrieval / Memory / Agent-Tool 루프)
⚠️ 중요 변화: 기존 LangChain의 기본 에이전트 클래스(AgentExecutor)는 루프 제어력의 한계로 인해 현재 Deprecated(지원 중단) 수순을 밟고 있습니다. 현재는 에이전트 구축을 위한 새로운 공식 표준인 LangGraph를 사용하는 방향으로 생태계가 개편되었습니다.
03

Chain vs Agent

"연결 방식을 누가 결정하는가"에 따른 구분 → 실행 순서 고정 여부가 핵심 차이

CHAIN

고정된 순서 · 예측 가능한 파이프라인

  • 개발자가 실행 순서를 사전에 명시
  • Prompt → LLM → Parser 등 선형 결합
  • 디버깅 · 테스트 용이, 비용 예측 가능
  • 단순 요약 · 번역 · 고정 포맷 추출에 적합
AGENT

LLM이 스스로 다음 행동을 판단

  • 어떤 Tool을, 몇 번, 어떤 순서로 쓸지 모델이 결정
  • ReAct 패턴 : 추론(Reason) ↔ 행동(Act) 반복
  • 동적 · 유연하지만 결과 예측 어려움
  • 복합 질의 · 다단계 리서치 작업에 적합
04

LCEL(LangChain Expression Language) 예시

파이프 연산자(|)로 컴포넌트를 사슬처럼 연결

chain = prompt | model | parser
# 1) 프롬프트 템플릿 정의 prompt = ChatPromptTemplate.from_template( "{topic}에 대해 세 문장으로 설명해줘" ) # 2) 모델 정의 model = ChatOpenAI(model="gpt-4o-mini") # 3) 출력 파서 정의 parser = StrOutputParser() # 4) 파이프로 연결 → 하나의 Chain 완성 chain = prompt | model | parser result = chain.invoke({"topic": "LangChain"})
05

생태계

LangChain 코어를 중심으로 관찰(Observability) · 오케스트레이션 · 배포 영역까지 확장

Langfuse
오픈소스 LLM 트레이싱 · 디버깅 · 평가 플랫폼 ➡️ LangSmith의 대안으로 널리 쓰이는 대표적 LLMOps 관찰 도구
LangGraph
그래프 기반 상태 관리 → 멀티 에이전트 · 사이클 있는 복잡한 워크플로우 오케스트레이션
LangServe
작성한 Chain을 REST API로 즉시 배포 → FastAPI 기반 서빙 레이어 자동 생성
06

LangChain vs LangGraph 핵심 비교

// 흐름 제어(Flow Control)와 상태 관리(State Management)의 차이

단순 순차 파이프라인은 LangChain이 우수하며, 사이클(Loop)이 존재하고 자체 복구가 필요한 복잡한 에이전트는 LangGraph가 최적입니다.

비교 항목LangChainLangGraph
동작 모델선형 체인 (DAG, 순차 실행)순환 그래프 (Node & Edge 기반)
상태 관리무상태(Stateless) 기본State 객체를 활용한 중앙 집중형 상태 관리
주요 특징빠른 빌드, 디버깅 용이, 안정적루프(Loop), 분기 및 조건부 복귀(Self-correction)
에이전트 패턴단일 ReAct 루프 등 단순 에이전트멀티 에이전트(Multi-agent) 협업 파이프라인
권장 케이스RAG 기반 Q&A, 정형 데이터 추출 및 요약자율 코딩 봇, 리서치 에이전트, 고객 지원 챗봇
LangChain 소개 자료 · 교육용 시각화
