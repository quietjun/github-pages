LangChain 소개 여러 개의 LLM 호출·도구·데이터를 사슬(Chain)처럼 엮는 프레임워크

LangChain은 프롬프트, 모델, 검색, 메모리, 도구를 표준 인터페이스로 연결하여 단발성 LLM 호출을 넘어선 복합 워크플로우 및 자율 에이전트 구성을 지원하는 오픈소스 프레임워크이다.

"LangChain의 핵심 모듈 아키텍처와 LCEL 표기법, 그리고 LangGraph와의 구조적 차이점 및 생태계를 종합 정리한다."

1. 등장 배경: LLM 단독 호출의 한계

GPT, Claude 등 모델 API를 단독 호출하는 방식만으로는 실제 서비스 구축에 한계가 존재하며, 다음과 같은 4가지 주요 기능 공백이 발생한다.

1. 프롬프트 관리 부재

템플릿화, 버전 관리 및 재사용 구조가 없어 문자열 하드코딩이 반복됨

2. 외부 데이터 단절

학습 시점 지식만 보유하여 사내 문서, DB 및 최신 데이터 접근 불가

3. 상태(맥락) 미유지

API 호출이 기본적으로 무상태(stateless)여서 대화 기록을 직접 관리해야 함

4. 행동(Action) 불가

계산, 검색, API 호출 등 실제 작업 수행 능력이 없어 단순 텍스트 생성에 국한됨

➔ LangChain 솔루션: 위 4가지 공백을 각각 Prompt, Retrieval, Memory, Tool 모듈로 표준화하여 해결함

2. 핵심 구성요소

입력부터 출력까지, 각 단계를 독립된 컴포넌트로 분리하여 자유롭게 사슬(Chain)처럼 조합한다.

⚠️ 중요 변화: 기존 LangChain의 기본 에이전트 클래스(AgentExecutor)는 루프 제어력의 한계로 인해 현재 Deprecated(지원 중단) 수순을 밟고 있다. 현재는 에이전트 구축을 위한 새로운 공식 표준인 LangGraph를 사용하는 방향으로 생태계가 개편되었다.

3. Chain vs Agent 비교

"연결 방식을 누가 결정하는가"에 따른 구분이며, 실행 순서의 고정 여부가 핵심 차이점이다.

⛓️ CHAIN (고정 파이프라인)

개발자가 사전에 정의한 순서대로 실행

  • Prompt ➔ LLM ➔ Parser 등 선형 단방향 결합
  • 디버깅, 테스트 용이 및 비용 예측 가능
  • 단순 요약, 번역, 정형 포맷 데이터 추출에 적합
🤖 AGENT (동적 자율 판단)

LLM이 스스로 다음 행동 및 도구 순서 결정

  • ReAct 패턴: 추론(Reason) ↔ 행동(Act) 과정 반복
  • 동적이고 유연하지만 경로 및 결과 예측이 어려움
  • 복합 질의 및 다단계 문제 해결 작업에 적합

4. LCEL (LangChain Expression Language) 표기법 예시

파이프 연산자(|)를 사용하여 컴포넌트를 사슬처럼 직관적으로 연결한다.

💻 LCEL 파이프라인 구성 예제 코드

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# 1) 프롬프트 템플릿 정의
prompt = ChatPromptTemplate.from_template("{topic}에 대해 세 문장으로 설명해줘")

# 2) LLM 모델 정의
model = ChatOpenAI(model="gpt-4o-mini")

# 3) 출력 파서 정의
parser = StrOutputParser()

# 4) 파이프로 연결하여 하나의 Chain 완성
chain = prompt | model | parser

# 5) 체인 실행
result = chain.invoke({"topic": "LangChain"})
print(result)

5. LangChain 생태계

LangChain 코어를 중심으로 관찰(Observability), 오케스트레이션 및 배포 영역까지 확장된 생태계 구조이다.

🟢 Langfuse

오픈소스 LLM 트레이싱, 디버깅 및 평가 플랫폼 (LangSmith의 대안으로 쓰이는 대표적 LLMOps 관찰 도구)

🔵 LangGraph

그래프 기반 상태 관리 프레임워크 (멀티 에이전트 및 사이클이 포함된 복잡한 워크플로우 오케스트레이션)

🟠 LangServe

작성한 Chain을 REST API로 즉시 배포 (FastAPI 기반 서빙 레이어 자동 생성 제공)

6. LangChain vs LangGraph 핵심 비교

흐름 제어(Flow Control)와 상태 관리(State Management) 방식에 따른 두 기술의 핵심 차이점이다.

⚖️ 기술 속성 비교표

비교 항목 LangChain LangGraph
동작 모델 선형 체인 (DAG, 순차 실행) 순환 그래프 (Node & Edge 기반)
상태 관리 무상태(Stateless) 기본 State 객체 기반 중앙 집중형 관리
주요 특징 빠른 빌드, 디버깅 용이, 안정적 루프, 분기 및 조건부 복귀(Self-correction)
에이전트 패턴 단일 ReAct 루프 등 단순 에이전트 멀티 에이전트(Multi-agent) 협업 파이프라인
권장 케이스 RAG Q&A, 정형 데이터 추출 및 요약 자율 코딩 봇, 리서치 에이전트, 고객 지원 챗봇

7. 강의 핵심 요약

  • 등장 배경: Prompt, Retrieval, Memory, Tool 모듈을 표준화하여 LLM 단독 호출의 한계 극복
  • Chain vs Agent: 고정된 순서의 선형 파이프라인(Chain) vs 모델이 동적으로 도구를 결정하는 자율 판단(Agent)
  • LCEL 표기법: 파이프 연산자(|)로 컴포넌트를 사슬처럼 선언적으로 결합
  • LangGraph 발전: 단순 선형 흐름은 LangChain, 순환 루프 및 상태 유지가 필요한 복잡한 에이전트는 LangGraph 채택
