파인튜닝 기법의 핵심 원리 · Low-Rank 개념 · 동작 방식 · 코드 사용법

이번 포스트에서는 파인튜닝 기법의 핵심 원리인 LoRA(Low-Rank Adaptation)의 개념과 동작 방식을 이해하고 실무 코드 적용 방법을 알아본다.

01 · PEFT 란?

PEFT
Parameter Efficient Fine-Tuning  ·  파라미터 효율적 미세조정

사전학습된 대규모 언어 모델(LLM)을 특정 태스크에 맞게 적응시키는 기법.
전체 파라미터를 재학습하는 대신, 소수의 파라미터만 학습하여 시간·메모리·저장 공간을 대폭 절약.
대표 기법 → LoRA (Low-Rank Adaptation) · Prefix Tuning · Adapter Tuning 등.

구분 ✖ 전체 파인튜닝 Full Fine-Tuning ✔ PEFT · LoRA Parameter Efficient
학습 대상 모든 파라미터 업데이트 → 수십억 개 전부 학습 원본 가중치 동결 → 소수 Adapter 파라미터만 학습
메모리 사용량 매우 높음 수백 GB VRAM 요구 낮음 — 전체 대비 1/10 일반 소비자 GPU로 가능
저장 공간 ~50 GB / 모델 ~10 MB / Adapter → 모델 공유, Adapter만 교체
학습 파라미터 100% 0.1 ~ 1% → 학습 속도 2~3배 향상
학습 시간 며칠 ~ 수 주 단일 GPU, 몇 시간 내
다중 태스크 어려움 → 태스크마다 모델 복제 필요 쉬움 → Adapter 교체만으로 즉시 전환

02 · Low-Rank 란?

💡 핵심 발견과 Rank(계수)의 본질

사전학습된 LLM을 파인튜닝할 때, 가중치 변화(ΔW)는 낮은 내재 차원(low intrinsic dimension)을 가짐. 즉, 가중치 변화의 실질적인 정보량은 전체 겉보기 차원보다 훨씬 작음.

🎹 피아노 건반으로 이해하는 원리:
피아노 건반은 총 88개이지만 쉬운 동요 한 곡을 연주할 때는 단 5~6개의 건반(낮은 실질 차원)만 사용함. 이처럼 LLM 가중치도 수십억 개에 달하지만, 요약이나 번역 등 특정 태스크를 배울 때는 정보가 서로 겹치지 않는 독립적인 핵심 차원(Rank=2 정도)으로만 가중치들이 떼지어 움직임.
🚀 LoRA의 해법:
8×8 전체(64개)를 전부 학습하는 대신, 단 2개의 핵심 통로(Rank=2)만 거쳐 가도록 얇은 두 행렬 B(8×2)와 A(2×8)의 곱셈으로 분해하여 가볍게 학습함. (※ 두 행렬을 곱해 다시 원래의 8×8 결과를 얻는 방식이므로, 중간에 2×2 사각형 행렬이 생성되는 것이 아님)
▶ 행렬 연산 분해 시각화 — ΔW · x ≈ B · A · x (8×8 가중치 곱셈)

• 전체 가중치 ΔW 직접 학습 시: 4096 × 4096 = 1,677만 개 (16.7M) 파라미터 업데이트 필요
• LoRA 어댑터 분해 학습 시: (4096 × 8) + (8 × 4096) = 6만 5천 개 (65K)만 학습 ➡️ 99.6% 파라미터 절약!

04 · 트랜스포머 내 LoRA 적용 위치

🎯 Self-Attention Layer
q_proj Query 투영 LoRA ✔
k_proj Key 투영 선택적
v_proj Value 투영 LoRA ✔
o_proj Output 투영 선택적
⚙️ MLP (Feed-Forward) Layer
up_proj Up 투영 증폭 선택적
gate_proj Gate 투영 검증(제어/필터링) 선택적
down_proj Down 투영 압축 선택적
💡 일반적으로 q_proj + v_proj에만 적용해도 충분한 성능 달성 — 메모리 절감과 성능 간 균형이 가장 좋은 조합. 더 높은 성능이 필요하면 k_proj, o_proj까지 확장.

2. 추론 연산 방식 비교 (분리 vs 병합)

🔗 분리 방식 (일반)
출력 = W₀·x + B·A·x
→ 두 번 계산 후 합산
  • LoRA Adapter 교체 가능
  • 원본 W₀ 항상 보존
  • 여러 태스크 즉시 전환
  • 계산 두 번 → 약간 느림
⚡ 병합 방식 (최적화)
W' = W₀ + B·A  (사전 합산)
출력 = W'·x
→ 한 번 계산으로 끝
  • 추론 속도 빠름 (오버헤드 없음)
  • 원본과 동일 구조 유지
  • 병합 후 Adapter 교체 불가
  • 단일 태스크 배포에만 적합

06 · LoRA 어댑터 훈련 및 Trainer 구성 원리

LoRA 어댑터 행렬(B × A) 설정을 마쳤다면, 이를 실제 데이터와 결합하여 학습을 구동할 훈련기(Trainer)를 구성해야 한다.

🏃‍♂️ 학습 구동기: SFTTrainer
  • 데이터셋 토큰화 자동화: 일반 트레이너를 쓰면 텍스트 데이터를 토크나이저를 사용해 숫자(input_ids)로 바꾸고 길이를 자르고 패딩을 채워 넣는 코드를 수십 줄 짜야 하지만, SFTTrainer는 원본 데이터셋과 컬럼명 지정만으로 이 모든 전처리를 백그라운드에서 자동 해결.
  • LoRA 학습 루프 자동화: 이전 단계(get_peft_model)에서 조립 완료된 LoRA 모델을 전달받아, 원본 가중치는 동결한 채 오직 어댑터 가중치만 역전파로 업데이트하는 훈련 엔진 자동 구동.
📋 학습 명세서: SFTConfig
  • 기본 학습 설정 선언: 배치 사이즈, 학습률, 학습 횟수(Epochs) 등 핵심 훈련 파라미터 선언.
  • SFT 전용 스펙 지정: 최대 입력 토큰 길이(max_seq_length) 등 SFTTrainer 구동 시 필요한 전용 튜닝 규격 명시.

07 · LoRA 코드 사용법

LoRA 어댑터를 학습하고 활용하는 전체적인 파이프라인 코드이다. [Base Model & Tokenizer 로드] ➡️ [LoRA 어댑터 결합] ➡️ [SFTTrainer 학습 구동] ➡️ [어댑터 저장]으로 이어지는 핵심 훈련 구조를 코드 탭을 통해 확인할 수 있다. 

from unsloth import FastLanguageModel

# ── 1. Base Model & Tokenizer 로드 ──────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="meta-llama/Llama-2-7b-hf",
    max_seq_length=2048,
    dtype=None,                # None → 자동 감지 (BF16/FP16)
    load_in_4bit=True,         # QLoRA: 4-bit 실시간 양자화 로드
)

# ── 2. LoRA Adapter 설정 (어댑터 구조 장착 및 가중치 동결) ───────────────────
model = FastLanguageModel.get_peft_model(
    model,
    r=16,                       # rank: 저순위 행렬 크기
    lora_alpha=32,              # scaling = alpha / r
    target_modules=["q_proj", "v_proj"],  # 타겟 레이어 지정
    lora_dropout=0.05,
    bias="none",
    use_gradient_checkpointing="unsloth",  # 메모리 추가 절감
    use_rslora=False,
)
model.print_trainable_parameters()
# 출력 예: trainable params: 4,194,304 / all params: 6,742,609,920 (0.06%)
from trl import SFTConfig, SFTTrainer

# ── 1. SFTTrainer 설정 (데이터 전처리 결합) ───────────────────────────────────
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,               # 텍스트 데이터셋
    dataset_text_field="text",           # 데이터셋 내의 텍스트 컬럼명 지정
    max_seq_length=2048,                # 최대 토큰 길이
    dataset_num_proc=2,
    packing=False,
    args=SFTConfig(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        warmup_steps=5,
        max_steps=60,
        learning_rate=2e-4,
        fp16=True,                       # 일반 GPU용 가속
        logging_steps=1,
        output_dir="outputs",
    ),
)

# ── 2. 학습 구동 및 완성된 Adapter 저장 ───────────────────────────────────────
trainer.train()                          # 훈련 바퀴 작동
model.save_pretrained("./lora-adapter")  # 가벼운 어댑터 파일 저장 (~10MB)
tokenizer.save_pretrained("./lora-adapter")
from unsloth import FastLanguageModel

# ── 1. 저장된 Adapter 로드 ───────────────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter",  # 저장해둔 Adapter 경로
    max_seq_length=2048,
    dtype=None,
    load_in_4bit=True,
)

# ── 2. 추론 모드 전환 (속도 최적화 커널 활성화) ─────────────────────────────
FastLanguageModel.for_inference(model)

# ── 3. 추론 ─────────────────────────────────────────────────────────────────
inputs = tokenizer("회의록을 요약해줘: ...", return_tensors="pt").to("cuda")

outputs = model.generate(
    **inputs,
    max_new_tokens=256,
    temperature=0.7,
    do_sample=True
)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

# ── 4. 다른 Adapter로 교체 (동일 Base 재사용) ───────────────────────────────
model2, tokenizer2 = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter-code",
    max_seq_length=2048, dtype=None, load_in_4bit=True,
)
# → Base Model(~16GB)은 그대로, Adapter(10MB)만 교체
from unsloth import FastLanguageModel

# ── 1. Adapter 로드 ──────────────────────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter",
    max_seq_length=2048,
    dtype=None,
    load_in_4bit=True,
)

# ── 2. Adapter 병합 → W' = W₀ + B·A ────────────────────────────────────────
merged_model = model.merge_and_unload()
# → 일반 모델과 동일한 구조 · 추론 오버헤드 없음
# → 단, 병합 후 Adapter 교체 불가

# ── 3. 병합 모델 저장 (FP16으로 변환 후 저장) ───────────────────────────────
merged_model.save_pretrained_merged(
    "./merged-model",
    tokenizer,
    save_method="merged_16bit",    # "merged_4bit" · "lora" 옵션도 가능
)

# ── 4. 병합 모델 추론 ────────────────────────────────────────────────────────
FastLanguageModel.for_inference(merged_model)
inputs = tokenizer("회의록을 요약해줘: ...", return_tensors="pt").to("cuda")
outputs = merged_model.generate(**inputs, max_new_tokens=256)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
