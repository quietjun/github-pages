PEFT Series 01

LoRA (Low-Rank Adaptation)

저순위 어댑터(Low-Rank) 분해 기법을 활용한 매개변수 효율적 파인튜닝의 원리와 실무 구현 가이드

1. PEFT 개념

PEFT(Parameter Efficient Fine-Tuning)는 사전학습된 거대 모델의 성능을 유지하며 특정 하위 작업에 맞춰 적응시키는 매개변수 효율적 미세조정 기법이다. 모든 가중치를 수정하는 대신 원본 가중치는 고정한 뒤 극소수의 파라미터만 학습하는 패러다임이다.

Parameter-Efficient Fine-Tuning

파라미터 효율적 미세조정

수십억 개의 전체 가중치 파라미터를 전부 튜닝(Full Fine-Tuning)하는 대신, 원본 모델은 읽기 전용(Freeze)으로 동결하고 추가된 소규모 어댑터(Adapter) 가중치만 학습함으로써 컴퓨팅 자원과 저장 용량을 획기적으로 낮춘다. 대표적인 기법이 LoRA(Low-Rank Adaptation)이다.

구분 ✖ 전체 파인튜닝 (Full Fine-Tuning) ✔ PEFT · LoRA
학습 대상 모델 매개변수 전량 업데이트 원본 가중치 동결 및 소수 어댑터만 학습
메모리 요구량 매우 높음 (수백 GB 이상의 VRAM 필수) 낮음 (전체 대비 1/10 수준으로 소비자 GPU 구동 가능)
저장 공간 모델당 수십 GB 필요 어댑터당 수십 MB 수준 (재사용 및 전환 용이)
학습 가중치 비중 100% 전체 학습 약 0.1% ~ 1.0% 범위
다중 작업 대응 불가능 (작업별 전체 모델 복제 필수) 용이함 (동일 기본 모델 위에 어댑터만 교체 서빙)

2. Low-Rank 동작 원리

💡
내재적 저차원(Low Intrinsic Dimension)의 본질

거대 언어 모델이 특정 도메인 작업에 맞춰 적응할 때, 가중치의 실질적인 변화량(ΔW)은 매개변수 표현 전체 공간보다 훨씬 좁은 낮은 차원(Low-Rank) 공간 내에서만 떼지어 발생한다는 것이 관찰되었다.

🎹 피아노 건반의 비유 피아노 건반은 총 88개에 달하나, 특정 곡을 연주할 때는 소수의 5~6개 건반(낮은 차원)만 집중 사용한다. LLM 역시 수십억 개의 다차원 가중치를 가졌으나 요약, 분류 등 단일 작업을 익힐 때는 정보가 겹치지 않는 극소수의 차원(Rank = 2~8)으로 수렴하여 동작한다.
🚀 행렬 분해 해법 (Matrix Decomposition) 기존 d × d 모양의 전체 가중치 변화 행렬 ΔW(예: 8×8 = 64개 파라미터)를 직접 조절하는 대신, 랭크 차원 r을 경유하도록 통로를 압축하여 B(d×r, 8×2)와 A(r×d, 2×8) 두 개의 얇은 행렬 곱으로 나누어 학습 효율을 향상한다.
▶ 가중치 변화 행렬 분해 시각화 : ΔW · x ≈ B · A · x (8×8 가중치 곱셈)

💡 실무적 차원 스케일 절감 효과 (d = 4096, Rank = 8 기준):
  • 기존 ΔW 직접 업데이트 시: 4096 × 4096 = 16,777,216개 파라미터 학습 필요
  • LoRA 어댑터 분해 업데이트 시: (4096 × 8) + (8 × 4096) = 65,536개 파라미터만 학습 ➡️ 99.61% 파라미터 생략

3. 순전파 & 역전파 흐름

학습 수행 시 입력 활성화값 x는 동결된 원본 가중치 W0와 학습 대상인 두 어댑터 A, B로 동시에 분기되어 연산된다.

4. 트랜스포머 적용 위치

LoRA 어댑터는 트랜스포머 아키텍처 내부의 선형 투영 레이어(Linear Projection Layers)에 삽입된다. 학습 대상 레이어의 범위 설정에 따라 자원 사용과 학습 능력이 변한다.

🎯 Self-Attention Layer (자가어텐션 부)
q_proj Query 투영 매핑 LoRA 적용
k_proj Key 투영 매핑 선택 선택
v_proj Value 투영 매핑 LoRA 적용
o_proj Output 출력 투영 선택 선택
⚙️ MLP / Feed-Forward Layer (순방향 피드 포워드)
up_proj Up 투영 매핑 차원 증폭 선택 선택
gate_proj Gate 게이트 제어 필터 필터 선택 선택
down_proj Down 압축 투영 차원 복구 선택 선택
📌
실무 권장 셋업 가이드

가장 일반적이고 가성비가 높은 조합은 q_proj와 v_proj에만 어댑터를 배치하는 방식이다. 성능 확보가 최우선인 경우엔 MLP(FFN) 영역까지 어댑터를 골고루 주입해야 하나, 어댑터 파라미터 용량과 메모리 오버헤드가 증가함을 고려하여 적합하게 배분해야 한다.

📌 실제 시나리오: 서비스 운영 시 고용량의 Base 모델(16GB)은 GPU VRAM에 완전히 박제시켜 둔 상태에서, 요청되는 목적에 맞춰 단 10MB짜리 특정 어댑터 파일만 교체(Hot-switching)하여 각각의 특화 태스크를 기동한다. 모델 복제본 배포가 필요 없어 막대한 메모리 비용을 방지한다.

2. 추론 연산 방식 비교 (분리 vs 병합)

🔗 분리 방식 (On-the-fly 계산)
출력 y = W₀ · x + B · A · x
→ 두 번의 행렬 연산을 순차 진행해 덧셈
  • 동적으로 어댑터 파일 교체 가능
  • 원본 기본 모델(W₀) 무훼손 보존
  • 두 번의 계산 과정으로 약간의 추론 오버헤드 유발
⚡ 병합 방식 (Zero-overhead 합산)
W' = W₀ + B · A (사전 융합)
출력 y = W' · x
→ 단일 연산으로 최종 출력 계산 완료
  • 연산 낭비 제로 (원본 구조와 속도 동일)
  • 추가 덧셈 연산 오버헤드 소거
  • 병합 완료 후 어댑터 스위칭 분리 불가

6. Trainer 구성 원리

LoRA 결합 구동을 위해 데이터 가공 및 모델 학습 루프 제어를 담당하는 Hugging Face TRL 훈련 라이브러리의 핵심 축이다.

🏃‍♂️
학습 엔진: SFTTrainer
  • 데이터 전처리 자동화: 원시 데이터셋 입력 시 텍스트 토큰화, 자르기(Truncation), 패딩 처리를 내부적으로 자동 변환함.
  • PEFT 어댑터 루프 제어: get_peft_model로 감싸진 LoRA 모델을 인지하여, 동결된 레이어 외의 어댑터 영역만 그라디언트를 계산해 훈련을 자동 수행함.
📋
학습 명세서: SFTConfig
  • 학습 하이퍼파라미터 정의: 배치 크기(batch_size), 가속 엔진 학습률(learning_rate), 최적화 스케줄 지정.
  • SFT 스펙 명시: 훈련에 활용될 최대 토큰 길이 규격(max_seq_length) 등 Trainer 동작 전용 구조 지정.

7. 코드 구현 가이드

unsloth 및 TRL 라이브러리를 활용해 모델을 불러오고 LoRA 어댑터를 설계 및 훈련시켜 배포하는 전체 엔드투엔드 소스코드 가이드이다.

from unsloth import FastLanguageModel

# ── 1. Base Model & Tokenizer 로드 ──────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="meta-llama/Llama-2-7b-hf",
    max_seq_length=2048,
    dtype=None,                # None 설정 시 자동 감지 적용 (BF16/FP16)
    load_in_4bit=True,         # QLoRA: 4-bit 양자화 활성화 로드
)

# ── 2. LoRA Adapter 설정 (어댑터 부착 및 타겟 지정) ───────────────────────────
model = FastLanguageModel.get_peft_model(
    model,
    r=16,                       # rank: 저순위 행렬 곱 크기
    lora_alpha=32,              # scaling = lora_alpha / r
    target_modules=["q_proj", "v_proj"],  # 타겟 투영 모듈 선언
    lora_dropout=0.05,
    bias="none",
    use_gradient_checkpointing="unsloth",  # 추가 메모리 절감 스펙
    use_rslora=False,
)
model.print_trainable_parameters()
# 출력 예: trainable params: 4,194,304 / all params: 6,742,609,920 (0.06%)
from trl import SFTConfig, SFTTrainer

# ── 1. SFTTrainer 가공 설정 (데이터 및 하이퍼파라미터 정의) ──────────────────────
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,               # 전용 텍스트 데이터셋
    dataset_text_field="text",           # 파일 내부 텍스트 컬럼 지정
    max_seq_length=2048,                # 입력 시퀀스 리미트
    dataset_num_proc=2,
    packing=False,
    args=SFTConfig(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        warmup_steps=5,
        max_steps=60,
        learning_rate=2e-4,
        fp16=True,                       # 16비트 연산 가속
        logging_steps=1,
        output_dir="outputs",
    ),
)

# ── 2. 학습 구동 및 생성 어댑터 가중치 디렉토리 저장 ──────────────────────────────
trainer.train()                          # 훈련 실행
model.save_pretrained("./lora-adapter")  # 완성된 소량의 어댑터(~10MB) 디스크 저장
tokenizer.save_pretrained("./lora-adapter")
from unsloth import FastLanguageModel

# ── 1. 저장된 어댑터 경로 로드 (동일 Base 자동 참조) ─────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter",  # 로컬 저장된 어댑터 정보
    max_seq_length=2048,
    dtype=None,
    load_in_4bit=True,
)

# ── 2. 추론 최적화 스펙 전환 ────────────────────────────────────────────────
FastLanguageModel.for_inference(model)

# ── 3. 가중치 추론 가동 ─────────────────────────────────────────────────────
inputs = tokenizer("회의록을 요약해줘: ...", return_tensors="pt").to("cuda")
outputs = model.generate(
    **inputs,
    max_new_tokens=256,
    temperature=0.7,
    do_sample=True
)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

# ── 4. 핫스위칭 어댑터 교환 ──────────────────────────────────────────────────
# Base 가중치를 캐시 상에 둔 상태로 10MB 크기의 타겟 어댑터만 즉시 전환 로딩
model2, tokenizer2 = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter-code",
    max_seq_length=2048, dtype=None, load_in_4bit=True,
)
from unsloth import FastLanguageModel

# ── 1. 병합 대상 어댑터 호출 ─────────────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="./lora-adapter",
    max_seq_length=2048,
    dtype=None,
    load_in_4bit=True,
)

# ── 2. 가중치 융합 연산 병합 처리 (W' = W₀ + B·A) ────────────────────────────
merged_model = model.merge_and_unload()
# → 어댑터 연산 단계를 소거하여 일반 1차 모델 형태로 결합
# → 융합 완료 이후에는 어댑터 개별 스위칭이 불가함

# ── 3. 결합된 16비트 모델로 디스크 최종 보존 ─────────────────────────────────
merged_model.save_pretrained_merged(
    "./merged-model",
    tokenizer,
    save_method="merged_16bit",    # FP16 정밀도 보존 병합
)
