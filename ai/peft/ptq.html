Post-Training Quantization 및 Test-time Prompting 워크플로우

Quantization & TTP 핵심 가이드

이번 포스트에서는 LLM 배포 단계에서 모델의 크기를 극적으로 줄이는 PTQ(Post-Training Quantization)의 핵심 원리를 알아본다. 아울러 양자화로 인해 발생하는 경계 입력(Edge Cases)에서의 품질 하락 문제를 추가 학습 없이 회복하는 TTP(Test-time Prompting) 보정 전략을 상세히 비교 및 정리한다.

추론 최적화 이원화 전략

INT4 PTQ로 가볍게 압축하고, TTP 프롬프트로 똑똑하게 보정한다!

LLM 배포 환경에서는 모델 크기로 인한 메모리 한계를 극복하는 PTQ 기법과, 양자화로 취약해진 입력에 대응해 정답 정밀도를 회복하는 TTP 기법이 유기적인 파이프라인을 구축한다.

1. QLoRA(학습 시 양자화) vs PTQ(추론 시 양자화) 관점의 차이

양자화가 실행되는 단계(학습 단계 vs 추론 단계)에 따라 핵심 가치와 아키텍처가 달라진다.

학습 시 양자화 (QLoRA)
Fine-tuning 시점
  • 목적: 제한된 GPU 자원으로 대형 모델 파인튜닝 수행
  • 방식: 가중치는 4-bit NF4로 고정하고 LoRA 어댑터(FP16)만 활성화하여 훈련
  • 특징: 가중치 업데이트가 역전파를 거쳐 어댑터 파라미터에만 전달됨
추론 시 양자화 (PTQ)
Inference 시점
  • 목적: 서비스 배포 시 추론 속도 개선 및 VRAM 메모리 소요 절감
  • 방식: 학습 완료본 모델 전체 가중치를 INT4 또는 FP4 규격으로 양자화하여 로드
  • 특징: 별도의 재학습 없이 즉각 배포 가능하며 소형 GPU 자원 활용도 극대화

2. PTQ (Post-Training Quantization) 핵심 원리 & 구현

학습이 끝난 모델의 가중치를 4-bit 규격으로 압축하여 소비자용 GPU 메모리에 로드하는 방법이다.

추론 시 메모리 구성 요소 (가중치 vs 활성화/KV 캐시)

핵심 포인트: 양자화는 모델의 가중치(Weights)를 16-bit에서 4-bit로 압축하여 물리 저장 공간과 가중치 VRAM 점유율을 75% 수준으로 삭감한다. 반면 추론 과정의 활성화값과 KV 캐시 영역은 연산 정밀도 유지를 위해 FP16을 유지한다.
bitsandbytes 기반 INT4 PTQ 모델 로딩 코드 Transformers Pipeline 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

# 1. INT4 양자화 세부 셋업 선언 (Normal Float 4-bit 양자화 적용)
quant_config = BitsAndBytesConfig(
    load_in_4bit=True,                          # 4-bit 압축 모드 작동
    bnb_4bit_compute_dtype=torch.float16,       # 활성화 텐서 연산 dtype을 FP16으로 강제
    bnb_4bit_quant_type="nf4",                  # 가중치 최적화 NF4 타입 사용
    bnb_4bit_use_double_quant=True,             # 메타데이터 자체의 이중 압축 추가 적용
)

# 2. 파인튜닝 없이 Base Model을 INT4 PTQ 형태로 즉시 로드
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct",
    quantization_config=quant_config,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")

3. 양자화 모델의 한계: 경계 입력(Edge Cases) 품질 저하

INT4 압축 모델은 정상적인 지문에서는 성능을 유지하나, 오타나 추임새 등 정보 밀도가 떨어지는 입력값에서 한계를 보인다.

1. 오타 (Typo)

예: "서울에셔 부산까지..."

양자화 오차 누적으로 어텐션 스코어 왜곡이 생겨 단어 파악 실패 유도.

2. 노이즈 (Noise)

예: "음... KTX로 대략...?"

불필요한 공백과 삽입구가 추가되면서 정밀도가 무너진 토큰의 답변 궤적 이탈.

3. 모호함 (Ambiguity)

예: "그거 얼마나 걸려?"

맥락이 흐려질 때 모델의 확률적 답변 판별 한계가 좁아져 엉뚱한 대답 도출.

4. 조건 변화

예: "밤 11시 출발 시 다음날..."

여러 제약조건 연산 시 양자화 오차가 점진적으로 전파되어 연산 능력 조기 유실.

4. TTP (Test-time Prompting) 품질 보정 전략

모델의 가중치를 직접 미세조정하지 않고, 추론 단계의 프롬프트 강화만으로 정상 범주의 출력 정밀도를 회복한다.

TTP-A: 출력 형식 & 제약조건 강화
지시문 명시

모델이 준수해야 할 추론 가이드(오타 무시 규칙, 단위 고정)를 직접 시스템 프롬프트 형태로 조율하여 탈선 방지.

[프롬프트 템플릿 예시]
규칙 1: 오타나 불명확 표현이 있어도 의도를 파악하세요.
규칙 2: 대략적인 소요 시간(시간 단위)으로 답하세요.
질문: {question}
TTP-B: Few-shot 예시 포함
예시 제공

1~2개의 모범 입출력 구조(Few-shot)를 프롬프트에 내장하여 출력 타겟을 직관적으로 명시.

[프롬프트 템플릿 예시]
예시 Q: 서울역에서 대전역까지 KTX로 얼마나 걸려요?
예시 A: 서울역에서 대전역까지 KTX로 약 50분 소요됩니다.
질문: {question}

TTP 적용 전후 품질 회복 비교 테스트 (실습 결과 요약)

입력 유형 입력 예시 TTP 미적용 (INT4 전용) TTP-A/B 적용 후
정상 서울에서 부산까지 KTX로 얼마나 걸리나요? 정상 응답 (5/5) 정상 응답 유지 (5/5)
오타 서울에셔 부산까지 KTX로 얼마나 걸리나요? 의도 오파악 및 환각 (3/5) 오타 교정 후 완벽 응답 (5/5)
노이즈 서울에서 부산까지... 음... KTX로 대략? 답변 방황 (2/5) 핵심 소요시간 정밀 응답 (4.5/5)
모호함 그거 얼마나 걸려? 엉뚱한 대답 도출 (1/5) 교통 안내 맥락 자동 복원 (4/5)
