PTQ & TTP — 추론 양자화와 품질 보정 전략

Post-Training Quantization 및 Test-time Prompting 워크플로우 분석 가이드

LLM 배포 단계에서 모델의 크기를 극적으로 줄이는 PTQ(Post-Training Quantization)의 핵심 원리를 알아본다. 아울러 양자화로 인해 발생하는 경계 입력(Edge Cases)에서의 품질 하락 문제를 추가 학습 없이 회복하는 TTP(Test-time Prompting) 보정 전략을 상세히 비교 및 정리한다.

1. LLM 기술 적용 이원화 구조도

Base LLM을 중심으로 사용 목적에 따라 두 갈래로 나뉜다. 특정 업무 특화를 위해 저사양 GPU에서 학습할 때는 좌측 파인튜닝 트랙(LoRA ➔ QLoRA)을 선택하고, 학습된/사전학습 모델을 서비스 배포용으로 VRAM을 다이어트할 때는 우측 서빙 배포 트랙(PTQ ➔ TTP)을 선택한다.

학습(Fine-Tuning) ⬅️ Base LLM ➡️ 추론(Serving) 구조도 Dual-Track Branching

2. QLoRA(어댑터 학습 시 양자화) vs PTQ(추론 시 양자화) 관점의 차이

양자화가 실행되는 단계(어댑터 학습 단계 vs 추론 단계)에 따라 핵심 가치와 아키텍처가 달라진다.

비교 항목 🏋️‍♂️ 어댑터 학습 시 양자화 (QLoRA) ⚡ 추론 시 양자화 (PTQ)
적용 시점 파인튜닝 학습 단계. 추론 및 서비스 배포 단계.
핵심 목적 제한된 GPU 메모리 환경에서의 대형 모델 추가 학습. 서빙 VRAM 소요 최소화 및 동시 요청 처리력 개선.
동작 방식 Base 모델 가중치를 그대로 고정하고 4-bit 양자화 적재하여, 추가된 어댑터 가중치만 학습. Base 모델 가중치 전체를 INT4로 일괄 양자화하여 고정 적재.
메모리 절감 Gradient 및 가중치 VRAM 삭감 (24GB 단일 GPU로 70B 학습 유도). 가중치 VRAM 약 75% 절감 (1.5B 기준: FP16 3.5GB ➡️ INT4 ~1.8GB 안착).
품질 대응 어댑터 파인튜닝을 통한 특정 태스크 성능 보완 및 학습. 양자화 손실로 인한 경계 입력(오타/노이즈) 품질 저하 발생 (TTP 프롬프트 보정으로 대응).

3. PTQ (Post-Training Quantization) 핵심 원리 & 구현

학습이 끝난 모델의 가중치를 4-bit 규격으로 압축하여 소비자용 GPU 메모리에 로드하는 방법이다.

추론 시 모델 가중치 용량 변화
PTQ 구현을 위한 3대 핵심 객체 (Transformers & bitsandbytes)
1. BitsAndBytesConfig

Hugging Face의 8-bit / 4-bit 양자화 설정 클래스. 로드 방식(4bit), 계산 정밀도(compute_dtype), 양자화 타입(nf4) 등을 제어.

2. AutoModelForCausalLM

사전 학습된 LLM 기본 로더 클래스. BitsAndBytesConfig를 전달하면 원본 FP16 가중치를 4-bit(INT4)로 실시간 양자화하여 메모리에 적재.

3. AutoTokenizer

입력 텍스트를 수치형 토큰 ID로 변환하고 생성된 결과를 문장으로 복원하는 객체. 모델과 동일한 어휘 사전(pretrained)을 로드하여 사용.

bitsandbytes 기반 INT4 PTQ 모델 로딩 코드 Transformers Pipeline 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

# 1. INT4 양자화 세부 셋업 선언 (Normal Float 4-bit 양자화 적용)
quant_config = BitsAndBytesConfig(
    load_in_4bit=True,                          # 4-bit 압축 모드 작동
    bnb_4bit_compute_dtype=torch.float16,       # 활성화 텐서 연산 dtype을 FP16으로 강제
    bnb_4bit_quant_type="nf4",                  # 가중치 최적화 NF4 타입 사용
    bnb_4bit_use_double_quant=True,             # 메타데이터 자체의 이중 압축 추가 적용
)

# 2. 파인튜닝 없이 Base Model을 INT4 PTQ 형태로 즉시 로드
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct",
    quantization_config=quant_config,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")

4. 양자화 모델의 한계: 경계 입력(Edge Cases) 품질 저하

INT4 압축 모델은 정상적인 지문에서는 성능을 유지하나, 오타나 추임새 등 정보 밀도가 떨어지는 입력값에서 한계를 보인다.

환경 변화(Distribution Shift) 입력 테스트 시나리오
입력 유형 실습 테스트 예시 INT4 양자화 모델 품질 저하 현상 (실습 결과)
오타 (Typo) "서울에셔 부산까지 KTX로 얼마나 걸리나요?" 오타 단어("에셔") 분석 실패 및 의도 왜곡으로 엉뚱한 응답 출력.
노이즈 (Noise) "서울에서 부산까지... 음... KTX로 얼마나 걸리나요? 대략?" 구어체 추임새("음...") 및 중복 표현에 따른 답변 궤적 이탈.
모호함 (Ambiguity) "그거 얼마나 걸려?" 지시대명사 맥락 부족 및 추론 범주 축소로 엉뚱한 답변 도출.
조건 변화 "밤 11시에 출발하면 다음날 아침에 도착할 수 있나요?" 시간 계산 등 다중 논리 제약조건 처리 과정의 오차로 추론 실패.
양자화 모델이 환경 변화에 취약한 3대 원인
  • 1) 정밀도 오차의 점진적 전파: 가중치 축소 과정의 미세한 버림/반올림 오차가 모델의 수십억 개 레이어 연산을 거치며 누적됨.
  • 2) Self-Attention 맵 왜곡: 양자화 오차로 인해 Query-Key 간 유사도 계산이 어긋나면서 모델이 엉뚱한 토큰에 비정상적인 Attention을 집중시킴.
  • 3) 경계 케이스(Edge Case) 방어력 소실: 학습 빈도가 높은 정상 패턴은 가중치가 강해 압축을 견디지만, 빈도가 낮은 예외 패턴(오타 등)은 약한 가중치 영역에 분포하여 압축 시 정보가 파괴됨.
시각적 비유: 4K 고화질 vs 480p 저화질 압축 이미지

FP16 (4K 고해상도): 디테일이 살아있어 아주 작고 희미하게 적힌 글씨(오타/노이즈)도 뭉개짐 없이 식별 및 복구 가능.

INT4 (480p 압축 해상도): 전체 윤곽은 보이나 디테일 영역이 열화되어, 작은 흠집이나 오타가 들어오는 순간 판독 불가 수준으로 뭉개짐.

💡 결론: 입력이 불명확해질수록 모델의 "추론적 여유 영역"이 삭감되므로, 파인튜닝을 할 수 없는 상황이라면 프롬프트를 보정하는 TTP(Test-time Prompting) 전략이 필수적임.

5. TTP (Test-time Prompting) 품질 보정 전략

모델의 가중치를 직접 미세조정하지 않고, 추론 단계의 프롬프트 강화만으로 정상 범주의 출력 정밀도를 회복한다.

TTP-A: 출력 형식 & 제약조건 강화
지시문 명시

추론 가이드(오타 무시 규칙 등)를 직접 시스템 프롬프트 형태로 조율하여 탈선을 방지한다.

[프롬프트 템플릿 예시]
규칙 1: 오타나 불명확 표현이 있어도 의도를 파악하세요.
규칙 2: 대략적인 소요 시간(시간 단위)으로 답하세요.
질문: {question}
TTP-B: Few-shot 예시 포함
예시 제공

1~2개의 모범 입출력 구조(Few-shot)를 프롬프트에 내장하여 출력 타겟을 직관적으로 명시한다.

[프롬프트 템플릿 예시]
예시 Q: 서울역에서 대전역까지 KTX로 얼마나 걸려요?
예시 A: 서울역에서 대전역까지 KTX로 약 50분 소요됩니다.
질문: {question}
