Post-Training Quantization 및 Test-time Prompting 워크플로우

Quantization & TTP 핵심 가이드
추론 최적화 핵심 이원화 전략

"INT4 PTQ로 가볍게 압축하고, TTP 프롬프트로 똑똑하게 보정한다!"

LLM 실무 서비스 배포에서는 모델 크기로 인한 메모리 한계를 극복하는 PTQ(Post-Training Quantization)와, 양자화로 취약해진 경계 입력(Edge Cases)에서의 성능 저하를 추가 재학습 없이 회복하는 TTP(Test-time Prompting) 전략이 핵심 파이프라인을 이룹니다.

1. QLoRA(학습 시 양자화) vs PTQ(추론 시 양자화) 관점의 차이

양자화가 적용되는 시점(학습 단계 vs 추론 단계)에 따라 핵심 역할이 구분됩니다.

학습 시 양자화 (QLoRA)

Fine-tuning 시점
  • 목적: 제한된 GPU 메모리로 대형 모델 파인튜닝 수행
  • 방식: Base Model은 4-bit NF4로 고정(Freeze) + LoRA Adapter(FP16)만 학습
  • 특징: Gradient 역전파가 LoRA 파라미터에 전달됨

추론 시 양자화 (PTQ) ⭐

Inference 시점
  • 목적: 서비스 배포 시 추론 속도 향상 및 VRAM 메모리 극대 절감
  • 방식: 학습 완료 후 모델 전체 가중치를 INT4(4-bit)로 양자화하여 로드
  • 특징: 재학습 없음(No Gradient), 16GB VRAM에서 7B~70B 모델 추론 가능

2. PTQ (Post-Training Quantization) 핵심 원리 & 구현

학습이 끝난 모델을 INT4 양자화하여 소비자용 GPU 메모리에 안착시키는 방법입니다.

추론 시 메모리 구성 요소 (가중치 vs 활성화/KV 캐시)

핵심 포인트: 양자화는 모델 가중치(Weights)를 16-bit에서 4-bit로 압축하여 가중치 메모리를 약 75% 절감합니다. 하지만 추론 중 발생하는 활성화값 및 KV 캐시는 연산 정밀도를 위해 FP16을 유지하므로, 전체 피크 메모리는 가중치 절감분 + 알파 형태로 형성됩니다.
bitsandbytes 기반 INT4 PTQ 모델 로딩 코드 HuggingFace Transformers 연동 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

# 1. INT4 양자화 설정 (NF4 - Normal Float 4-bit)
quant_config = BitsAndBytesConfig(
    load_in_4bit=True,                          # INT4 양자화 활성화
    bnb_4bit_compute_dtype=torch.float16,       # 추론 연산 시 dtype은 FP16 사용
    bnb_4bit_quant_type="nf4",                  # LLM 가중치 정규분포 최적화 양자화
    bnb_4bit_use_double_quant=True,             # 이중 양자화로 메타데이터 메모리 추가 절감
)

# 2. PTQ 양자화 모델 로딩 (별도 파인튜닝 과정 없이 바로 로드)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct",
    quantization_config=quant_config,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")

3. 양자화 모델의 한계: 경계 입력(Edge Cases) 품질 저하

INT4로 압축된 모델은 정상 지문에서는 우수하지만, 불명확한 입력 시 정밀도 손실 누적으로 품질이 저하됩니다.

1. 오타 (Typo)

예: "서울에셔 부산까지..."

Attention Score 미세 오차로 단어 의미 파악 실패 및 엉뚱한 응답 발생.

2. 노이즈 (Noise)

예: "음... KTX로 대략...?"

불필요한 추임새나 불명확한 문장 요소로 인해 모델 추론 방황.

3. 모호함 (Ambiguity)

예: "그거 얼마나 걸려?"

맥락 생략 시 양자화로 좁아진 "추론 여유(Inference Margin)"로 잘못된 답변 선택.

4. 조건 변화

예: "밤 11시 출발 시 다음날..."

복합 제약조건 계산 시 양자화 오차가 누적되어 조건 유실.

4. TTP (Test-time Prompting) 품질 보정 전략

모델 가중치를 수정하지 않고, 추론 시점의 프롬프트 구성만으로 양자화 모델의 성능을 원상 복구합니다.

TTP-A: 출력 형식 & 제약조건 강화

지시문 명시

모델에게 처리 규칙(오타 허용, 단위 지정, 역활/맥락 부여)을 직접 지정하여 추론 방향을 안내합니다.

[프롬프트 템플릿 예시]
규칙 1: 오타나 불명확 표현이 있어도 의도를 파악하세요.
규칙 2: 대략적인 소요 시간(시간 단위)으로 답하세요.
질문: {question}

TTP-B: Few-shot 예시 포함

예시 제공

1~2개의 모범 입출력 샘플을 프롬프트에 동량 배치하여 원하지 않는 방향으로의 이탈을 방지합니다.

[프롬프트 템플릿 예시]
예시 Q: 서울역에서 대전역까지 KTX로 얼마나 걸려요?
예시 A: 서울역에서 대전역까지 KTX로 약 50분 소요됩니다.
질문: {question}

TTP 적용 전후 품질 회복 비교 테스트 (실습 결과 요약)

입력 유형 입력 예시 TTP 미적용 (INT4 전용) TTP-A/B 적용 후
정상 서울에서 부산까지 KTX로 얼마나 걸리나요? 정상 응답 (5/5) 정상 응답 유지 (5/5)
오타 서울에셔 부산까지 KTX로 얼마나 걸리나요? 의도 오파악/환각 (3/5) 오타 교정 후 완벽 응답 (5/5)
노이즈 서울에서 부산까지... 음... KTX로 대략? 답변 방황 (2/5) 핵심 소요시간 즉시 응답 (4.5/5)
모호함 그거 얼마나 걸려? 엉뚱한 주제 대답 (1/5) 교통 안내 맥락으로 복원 (4/5)
