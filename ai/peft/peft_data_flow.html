LLM 파인튜닝 데이터 가공 및 포맷팅 가이드

실습 5-1 기준: 데이터셋 전처리, ChatML 포맷팅, Response-Only 학습 파이프라인 시각화

체스 학습 데이터 전처리 파이프라인 4단계

체스 원본 기보 데이터셋이 토크나이저와 학습용 마스크를 거쳐 모델에 주입되기까지의 흐름이다.

Stage 01 · 데이터셋 로드 Raw JSON

태스크 지시어(task), 체스 기보 입력(input), 다음 예상수 정답(expected_output)이 각각 개별 필드로 파편화되어 로드된다. 

{
  "task": "Predict move...",
  "input": "1. e4 e5 2. Nf3",
  "expected_output": "Nc6"
}
Stage 02 · 대화형 모델 형식 구조 ChatML

system, user, assistant 역할군에 맞춰 대화 목록 형태로 재구성한다. 

"conversations": [
  {"role": "system", "content": "..."},
  {"role": "user", "content": "1. e4..."},
  {"role": "assistant", "content": "Nc6"}
]
Stage 03 · Chat Template 적용 및 중복 BOS 토큰 탈락 Formatting & Trim

토크나이저 템플릿을 거쳐 특수 지시어 마커를 이식한 뒤, Unsloth 학습 충돌을 막기 위해 맨 앞의 중복 <bos> 토큰을 명시적으로 제거한다. 

<start_of_turn>system
  Predict move...
<end_of_turn>
<start_of_turn>user
  1. e4 e5 2. Nf3
<end_of_turn>
<start_of_turn>model
  Nc6
<end_of_turn>
STAGE 03 실제 구현 formatting_prompts_func 
def formatting_prompts_func(examples):
    convos = examples["conversations"]
    texts = [
        tokenizer.apply_chat_template(
            convo,
            tokenize=False,                 # False → 토큰 ID가 아닌 포맷팅된 문자열 텍스트 반환
            add_generation_prompt=False    # 학습 시에는 정답 답변까지 포함해야 하므로 False 지정
        ).removeprefix('<bos>')            # 중복 BOS 토큰 제거
        for convo in convos
    ]
    return {"text": texts}

dataset = dataset.map(formatting_prompts_func, batched=True)
BOS (<bos>) 제거 사유

템플릿 가공 시 자동 삽입되는 문장 시작 토큰. SFTTrainer 훈련 시 중복 삽입되는 현상을 막아 학습 성능 및 속도 저하 방지.

add_generation_prompt 설정 가이드

학습 단계 (False): 질문과 정답 답변을 결합하여 전체 가중치를 훈련하기 위해 정답 본문까지 이어서 포맷팅.
추론 단계 (True): 질문 끝에 "어시스턴트 답변 시작"을 알리는 제어 토큰 주입.

Stage 04 · Response-Only 마스킹 설정 Loss Masking Labels

질문 영역의 손실(Loss) 계산을 제외하고 오직 모델 정답부(assistant/model) 영역만 가중치를 훈련시키는 설정.

1. 대화형 템플릿 내의 가중치 마스킹 도해

전체 대화 템플릿 중 학습 대상이 아닌 질문 영역은 취소선(Masked) 처리.

<start_of_turn> system Predict the next move in this chess game. <end_of_turn> <start_of_turn> user 1. e4 e5 2. Nf3 Nc6 3. Bb5 <end_of_turn> <start_of_turn> model a6 <end_of_turn>
2. 최종 PyTorch Label 텐서 형태

취소선 처리된 질문 영역 토큰의 레이블 ID를 -100 상수로 치환한 내부 데이터셋 형태. 

labels = [
  -100, -100, ..., -100, // user 영역
  2412, 532, 23412       // model 영역
]
Loss 무시 (Label = -100 ❄️) Loss 계산 (실제 토큰 🔥)
Unsloth 기반 Response-Only 설정 코드 
from unsloth.chat_templates import train_on_responses_only

trainer = train_on_responses_only(
    trainer,
    instruction_part="<start_of_turn>user\n",
    response_part="<start_of_turn>model\n",
)

목적에 따른 데이터 처리 흐름 분화

LLM 파인튜닝 시 데이터를 가공하는 목적에 따라 훈련(Train) 단계와 평가/추론(Evaluation/Inference) 단계의 전처리 흐름이 명확히 분화된다.

구분 🏋️‍♂️ 훈련 (Training) ⚡ 평가 / 추론 (Evaluation)
가공 목적 및 흐름 질문 뒤에 정답 답변까지 한 문장으로 결합한 완성형 상태로 가공하여 모델의 전 가중치를 훈련. 정답 답변을 가린 채 질문만 주입하고, 모델에게 "답변 시작" 제어 태그를 줘서 출력을 유도.
add_generation_prompt False (답변 뒤에 정답 본문을 곧바로 결합) True (문장 끝에 답변 시작 제어 헤더 강제 인젝션)
최종 가공 데이터 포맷 
<user> 질문 </user><assistant> 정답 답변 <eos>
 
<user> 질문 </user><assistant> (답변 대기 상태)
손실값 (Loss) 계산 범위 질문 영역은 -100 마스킹으로 손실 계산에서 제외, 오직 어시스턴트 정답 답변 토큰만 학습. 모델이 스스로 생성해내는 토큰들을 획득하여 원본 정답 답변 문장과 오차를 대조 및 평가.
