Quantization Concept

왜 하필 4-bit 양자화 (NF4) 인가요?

LLM 미세조정 시 가중치와 옵티마이저가 차지하는 막대한 VRAM 소모를 해결하기 위해, 원래 16-bit나 32-bit로 이루어진 모델 매개변수를 4-bit 크기로 압축하여 GPU에 적재하는 메커니즘입니다. 수치 정밀도가 낮아지지만 연산 및 추론의 오차 손실은 1~3% 내외로 통제되어 극단적인 가성비를 발휘합니다.

1B 모델 로딩에 필요한 순수 모델 가중치 VRAM
FP32 (전 정밀도, 4 bytes/param) 4.0 GB
FP16 (반 정밀도, 2 bytes/param) 2.0 GB
NF4 (QLoRA 4-bit, 0.5 bytes/param) 0.5 GB (87.5% 절감!)

LoRA: 저차원 분해 가중치 이식

기존 가중치 $W$는 완전히 얼려두고(Frozen), 입력 $x$에 대해 초소형 Rank 가로/세로 매트릭스 $A, B$를 우회로(Adapter)로 배치해 $BA$의 조그만 변화량만을 학습시킵니다.

LoRA 출력 수식
h = Wx + BAx
W (고정 ❄️) | A, B (1% 미만 학습 대상 🔥)
  • Rank (r) = 8: 분해 행렬 차원의 크기. r이 작을수록 파라미터 수 감소.
  • lora_alpha = 16: 스케일러 ($r \times 2$ 권장). 어댑터 출력 비율 조정.

    • 어댑터(Adapter) 저장 형태 가이드

    미세조정이 끝나면 가중치를 병합해서 배포할지, 아니면 가벼운 가중치 플러그인만 뽑아낼지 선택할 수 있습니다.

    1. Adapter만 분리 보관

    용량이 단 수십 MB 수준으로 매우 작아 신속한 배포 및 다목적 전환 탑재에 최고입니다.

    2. Base와 완전 병합

    추론 속도 향상을 위해 merge_and_unload()로 합쳐 단일 모델로 패키징합니다.

    이 실습에서는 gemma3-lora-chess 폴더에 Adapter 관련 파라미터와 토크나이저 파일만을 실무 권장 방식으로 분리 저장합니다.

    Response-Only Loss 가중치 제한 기법

    질문이나 시스템 지침 부분은 굳이 모델이 언어 생성 확률을 정렬할 필요가 없습니다. 자원의 소모를 차단하기 위해 오로지 모델의 답변 구역(Model Response)에서만 역전파 Loss 값을 추출해 집중 훈련하는 최첨단 효율 기법입니다.

    Loss 계산 무시 (가중치 변화 없음 ❄️)
    <start_of_turn>system ... user 1. e4 e5 ...<end_of_turn>
    Loss 계산 대상 (Gradient 가중치 업데이트 🔥)
    <start_of_turn>model\na6<end_of_turn>

    BOS (<bos>) 토큰 왜 제거할까요?

    HuggingFace 템플릿 처리 시 기본적으로 문장의 시작에 `` 토큰이 생성됩니다. 그러나 Unsloth나 고급 Trainer 파이프라인 연동 학습 및 추론 문자열 매핑 시, 문장 조각의 중간 결합 부위에 원치 않는 중복 `` 토큰이 삽입되는 템플릿 충돌 오류가 빈번합니다.

    실습 핵심 코드 디테일:

    tokenizer.apply_chat_template(...).removeprefix('<bos>')

    이 코드로 맨 앞의 불필요한 중복 시작 마커를 일괄 삭제하여 데이터 정렬 정밀도를 극대화합니다.
