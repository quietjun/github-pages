Spring AI 기반 Custom Agent 설계

Planner-Worker 패턴을 활용한 엔터프라이즈 에이전트 오케스트레이션

💡
Spring AI는 엔터프라이즈 환경에서 강력한 자바 기반 AI 연동을 제공한다. 이번 포스트에서는 Spring AI의 ChatClient 인터페이스를 오케스트레이션하여, 계획 수립(Planner)과 함수 호출 실행(Worker)을 명확히 이원화하는 Planner-Worker 패턴 Custom Agent를 Java로 구축한다.
01. Spring AI와 Custom Agent의 오케스트레이션

Python 진영의 LangGraph처럼 상태를 관리하고 노드를 분기하는 완벽한 그래프 프레임워크가 자바에 존재하지 않더라도, Spring Boot의 서비스 레이어(Service Layer)와 Java Record 기반의 상태 컨테이너를 조율하면 매우 안정적이고 강력한 Custom Agent를 만들 수 있다.

특히, Spring AI의 ChatClient는 흐름(System Prompt)과 동작 도구(Java Functions)를 Fluent API 형태로 명확히 바인딩할 수 있어, 다음과 같이 '계획자(Planner)'와 '실행자(Worker)'의 코드를 정교하게 분리해 내기에 최적의 요건을 갖추고 있다.

02. 실무 Java 구현 코드

스프링 부트 환경에서 Record를 활용해 스레드 세이프(Thread-safe)한 불변 상태 모델을 구성하고, ChatClient 인터페이스로 에이전트 노드를 구현하는 방식이다.

JAVA AgentState.java 
public record AgentState(
    String userRequest,   // 사용자 최초 요청 질문
    String plan,          // PlannerAgent가 정의한 실행 마일스톤
    String result         // WorkerAgent가 도출한 최종 상세 결과물
) {}
JAVA PlannerAgent.java 
@Service
public class PlannerAgent {
    private final ChatClient chatClient;

    public PlannerAgent(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("당신은 계획 수립 전담 Planner입니다. 사용자의 질문을 분석해 수행해야 할 작업을 Step 1, Step 2 형식의 텍스트 계획으로만 작성해 제출하세요.")
            .build();
    }

    public AgentState plan(AgentState state) {
        String plan = chatClient.prompt()
            .user(state.userRequest())
            .call()
            .content();
        return new AgentState(state.userRequest(), plan, null);
    }
}
JAVA WorkerAgent.java 
@Service
public class WorkerAgent {
    private final ChatClient chatClient;

    public WorkerAgent(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("당신은 계획 이행 전담 Worker입니다. 제공받은 계획을 분석하여 Spring Bean으로 연동된 API 도구를 적극 활용해 구체적인 수행 결과를 도출하세요.")
            .build();
    }

    public AgentState execute(AgentState state) {
        // Spring AI의 Fluent API를 기반으로 외부 등록 Bean Function 바인딩 및 계획 구동
        String result = chatClient.prompt()
            .user("계획: " + state.plan() + "\n요청사항을 실행해 최종 답변을 작성하세요.")
            .functions("couponRegistryFunction", "orderCheckFunction") // Spring @Bean Function 바인딩
            .call()
            .content();
        return new AgentState(state.userRequest(), state.plan(), result);
    }
}
JAVA AgentOrchestrator.java 
@Service
public class AgentOrchestrator {
    private final PlannerAgent plannerAgent;
    private final WorkerAgent workerAgent;

    public AgentOrchestrator(PlannerAgent plannerAgent, WorkerAgent workerAgent) {
        this.plannerAgent = plannerAgent;
        this.workerAgent = workerAgent;
    }

    public String runWorkflow(String userRequest) {
        // 초기 상태 객체 주입
        AgentState state = new AgentState(userRequest, null, null);
        
        // 1. Planner Agent 가동
        state = plannerAgent.plan(state);
        
        // 2. Worker Agent 가동 (도구 실행)
        state = workerAgent.execute(state);
        
        // 3. 최종 상태물 리턴
        return state.result();
    }
}
03. Spring AI 에이전트 아키텍처의 독보적인 강점

엔터프라이즈 레벨의 상용 서비스를 구축할 때, Java/Spring 진영에서 이원화 커스텀 에이전트를 도입하면 다음과 같은 강력한 이점을 얻는다.

1. 완벽한 Type-Safe 함수 바인딩 도구를 정의할 때 문자열 스키마를 직접 파이썬에서 하드코딩하는 방식과 달리, Java의 Function<Request, Response> 시그니처와 어노테이션 기반으로 Spring AI가 메타데이터 스키마를 JSON으로 안전하게 자동 빌드하므로 도구 오작동 및 타입 런타임 오류가 전무하다.
2. 불변 Record 기반의 완벽한 멀티스레드 안정성 Java 16부터 도입된 Record를 상태 보관소로 채택함으로써 다중 스레드 동시성 환경에서도 상태 오염 없이 안전하게 대규모 에이전트 오케스트레이션 루프를 스레드 안전하게 돌릴 수 있다.
