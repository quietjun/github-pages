Spring AI 기반 Custom Agent 설계: Planner-Worker 패턴

Spring AI의 ChatClient 인터페이스와 Java Record 불변 상태 모델을 결합하여, 계획 수립(Planner)과 도구 실행(Worker)을 정교하게 이원화하는 엔터프라이즈 에이전트 오케스트레이션을 구축한다.

1. Spring AI와 Custom Agent의 오케스트레이션

Spring Boot 환경에서는 서비스 계층(Service Layer)과 Java Record 기반 상태 컨테이너를 조합하여 매우 안정적인 Custom Agent를 설계할 수 있다.

특히 Spring AI의 ChatClient는 시스템 프롬프트(System Prompt)와 실행 도구(Java Functions)를 Fluent API 형태로 명확하게 바인딩할 수 있으므로, 계획자(Planner)와 실행자(Worker)의 역할을 명확히 격리하기에 최적화된 아키텍처를 제공한다.

Spring AI Custom Agent 오케스트레이션 아키텍처 다이어그램
역할 1
PlannerAgent (계획 수립 노드)

사용자의 원시 질문(Raw Query)을 면밀히 분석하여 수행해야 할 구체적 마일스톤(Step 1, Step 2 ...) 텍스트 계획만을 도출한다. 실행 도구(Tool)를 직접 호출하지 않고 순수 추론에만 집중한다.

역할 2
WorkerAgent (도구 실행 노드)

Planner가 생성한 세부 실행 계획을 전달받아, 스프링 빈으로 등록된 비즈니스 함수(Java Functions / Tools)를 적재적소에 호출하여 실제 데이터 조회 및 업무 로직을 수행한다.

2. 실무 Java 구현 코드

스프링 부트 환경에서 Record를 활용해 스레드 세이프(Thread-safe)한 불변 상태 모델을 정의하고, ChatClient 인터페이스로 각각의 에이전트 노드를 구현하는 방식이다.

State Model
AgentState.java (불변 상태 레코드)

Java 16+ Record를 활용하여 다중 스레드 환경에서도 안전한 불변 컨테이너를 구성한다.

public record AgentState(
    String userRequest,   // 사용자 최초 요청 질문
    String plan,          // PlannerAgent가 정의한 실행 마일스톤
    String result         // WorkerAgent가 도출한 최종 상세 결과물
) {}
Planner Node
PlannerAgent.java (계획 수립 전담 서비스)

시스템 프롬프트를 통해 외부 도구 호출 없이 순수 계획(Plan) 텍스트만을 생성하도록 제한한다.

@Service
public class PlannerAgent {

    private final ChatClient chatClient;

    public PlannerAgent(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("당신은 계획 수립 전담 Planner입니다. 사용자의 질문을 분석해 수행해야 할 작업을 Step 1, Step 2 형식의 텍스트 계획으로만 작성해 제출하세요.")
            .build();
    }

    public AgentState plan(AgentState state) {
        String plan = chatClient.prompt()
            .user(state.userRequest())
            .call()
            .content();
        return new AgentState(state.userRequest(), plan, null);
    }
}
Worker Node
WorkerAgent.java (도구 실행 전담 서비스)

스프링 컨텍스트에 등록된 @Bean Function들을 바인딩하여 계획에 따른 도구 호출을 수행한다.

@Service
public class WorkerAgent {

    private final ChatClient chatClient;

    public WorkerAgent(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("당신은 계획 이행 전담 Worker입니다. 제공받은 계획을 분석하여 Spring Bean으로 연동된 API 도구를 적극 활용해 구체적인 수행 결과를 도출하세요.")
            .build();
    }

    public AgentState execute(AgentState state) {
        // Spring AI의 Fluent API를 기반으로 스프링 빈 함수 바인딩 및 계획 구동
        String result = chatClient.prompt()
            .user("계획:\n" + state.plan() + "\n\n위 계획에 따라 요청사항을 실행하고 최종 답변을 작성하세요.")
            .functions("couponRegistryFunction", "orderCheckFunction") // Spring @Bean Function 바인딩
            .call()
            .content();
        return new AgentState(state.userRequest(), state.plan(), result);
    }
}
Orchestrator
AgentOrchestrator.java (전체 파이프라인 조율기)

초기 상태 생성부터 Planner ➔ Worker 순차 파이프라인을 단일 트랜잭션/메서드로 제어한다.

@Service
public class AgentOrchestrator {

    private final PlannerAgent plannerAgent;
    private final WorkerAgent workerAgent;

    public AgentOrchestrator(PlannerAgent plannerAgent, WorkerAgent workerAgent) {
        this.plannerAgent = plannerAgent;
        this.workerAgent = workerAgent;
    }

    public String runWorkflow(String userRequest) {
        // 1. 초기 불변 상태 생성
        AgentState state = new AgentState(userRequest, null, null);
        
        // 2. Planner Agent 가동 (계획 도출)
        state = plannerAgent.plan(state);
        
        // 3. Worker Agent 가동 (도구 호출 및 실행)
        state = workerAgent.execute(state);
        
        // 4. 최종 결과물 반환
        return state.result();
    }
}

3. Spring AI 에이전트 아키텍처의 독보적인 강점

엔터프라이즈 레벨의 상용 서비스를 구축할 때, Java 및 Spring Boot 기반의 이원화 커스텀 에이전트는 다음과 같은 독보적인 안정성과 생산성을 보장한다.

강점 1
완벽한 Type-Safe 함수 바인딩

도구를 정의할 때 문자열 스키마를 직접 하드코딩하는 방식과 달리, Java의 Function<Request, Response> 시그니처와 어노테이션 기반으로 Spring AI가 메타데이터 스키마를 JSON으로 안전하게 자동 빌드하므로 도구 오작동 및 런타임 타입 오류가 전무하다.

강점 2
불변 Record 기반의 멀티스레드 안정성

Java 16부터 도입된 Record를 상태 보관소로 채택함으로써 다중 스레드 동시성 환경에서도 상태 오염 없이 안전하게 대규모 에이전트 오케스트레이션 루프를 스레드 안전(Thread-safe)하게 구동할 수 있다.

아키텍처 결론

Spring AI의 Fluent API와 Spring Boot의 견고한 DI 생태계를 결합하면, 외부 대형 프레임워크에 대한 과도한 의존 없이도 순수 Java 코드로 유지보수성이 뛰어난 맞춤형 에이전트 오케스트레이션을 완성할 수 있다.
