Spring AI — Model Context Protocol (MCP) 완전 가이드

Spring AI 환경에서 @Tool 방식과의 구조적 차이점부터 MCP 3계층 아키텍처, Transport 전송 계층, 클라이언트·서버 실전 연동 코드까지 완벽하게 분석한다.

1. @Tool vs MCP — 무엇이 다른가

Spring AI의 Tool 통합 방식은 크게 인프로세스 방식의 @Tool과 프로토콜 기반의 아웃오브프로세스 방식인 Model Context Protocol(MCP)로 나뉜다.

@Tool 방식 Spring AI Native
  • In-Process 실행: 애플리케이션과 동일한 JVM 프로세스 내에서 직접 실행된다.
  • 어노테이션 기반: 일반 스프링 빈 메서드에 @Tool을 선언하여 손쉽게 등록한다.
  • 스키마 자동 생성: 자바 파라미터 타입을 기반으로 JSON Schema를 자동 추출한다.
  • 외부 공유 불가: 단일 스프링 애플리케이션 내부에서만 호출 가능하다.
  • 언어 종속성: Java 및 Kotlin 언어 환경에 종속된다.
MCP 방식 Anthropic 오픈 표준 프로토콜
  • Out-of-Process 실행: 독립된 자식 프로세스나 원격 네트워크 서버에서 실행된다.
  • 표준 프로토콜 통신: JSON-RPC 2.0 규격을 기반으로 요청과 응답을 직렬화한다.
  • 다양한 전송 계층: 환경에 맞춰 STDIO 또는 SSE(HTTP) Transport를 선택한다.
  • 높은 재사용성: 여러 AI 클라이언트(Claude Desktop, Cursor, Spring AI 등)에서 공용 사용이 가능하다.
  • 언어 독립성: Python, Node.js, Java, Go 등 다양한 언어로 구현할 수 있다.
@Tool vs MCP 상세 기능 비교표
비교 항목 @Tool 방식 (In-Process) MCP 방식 (Out-of-Process)
실행 위치 동일 JVM 프로세스 내부 독립 자식 프로세스 또는 원격 마이크로서비스
통신 메커니즘 메모리 상 메서드 직접 호출 JSON-RPC 2.0 (STDIO / SSE) 통신
선언 방법 @Tool 어노테이션 McpServerFeatures.SyncToolSpecification
도구 재사용성 단일 애플리케이션에 국한 다중 AI 에이전트 및 클라이언트 간 전역 공유
언어 독립성 Java / Kotlin 전용 모든 언어(Node.js, Python, Java 등) 구현 가능
동적 갱신(Hot-reload) 서버 재기동 필수 런타임 도구 목록 변경 알림(Tool Change Notification) 지원
제공 기능 범위 Tool(함수 실행) 단일 지원 Tool(실행) + Resource(컨텍스트) + Prompt(템플릿) 통합 제공
최적 권장 시나리오 단순 단일 앱 내부 비즈니스 연동 전사 공용 도구 허브 및 마이크로서비스 연계
코드로 보는 구현 방식 비교
@Tool 선언 (Java) 
@Service
public class WeatherService {
    @Tool(description = "도시의 실시간 날씨 조회")
    public String getWeather(@ToolParam String city) {
        return weatherApi.fetch(city);
    }
}

// ChatClient에 직접 등록
chatClient.tools(weatherService);
⚠️ 제약: 해당 스프링 애플리케이션 내에서만 동작하며 외부 AI 시스템과 도구를 공유할 수 없다.
MCP Server 등록 (Java) 
// MCP 서버 — 독립 프로세스 또는 마이크로서비스로 기동
var weatherTool = new McpServerFeatures.SyncToolSpecification(
    new Tool("get_weather", "현재 날씨 조회", schema),
    (exchange, args) -> {
        String city = (String) args.get("city");
        return new CallToolResult(List.of(
            new TextContent(weatherApi.fetch(city))
        ), false);
    }
);
✅ 이점: 서버를 한 번 배포하면 Claude Desktop, Cursor, 다른 AI 앱이 동시에 도구를 호출한다.

2. MCP 3계층 아키텍처 (Host · Client · Server)

MCP 아키텍처는 Host Application, MCP Client, MCP Server의 명확한 3단계 계층 구조로 이루어져 있으며, 표준 프로토콜을 통해 안전하게 외부 도구와 데이터를 연동한다.

MCP 3계층 시스템 아키텍처 다이어그램
1단계
Host Application

AI 모델을 주도적으로 구동하는 메인 스프링 부트 애플리케이션이다. 여러 개의 MCP Client를 통합 관리하며 ChatClient를 통해 대화를 조율한다.

2단계
MCP Client

개별 MCP 서버와의 1:1 통신 채널을 전담한다. McpSyncClient 또는 McpAsyncClient를 사용하며, 도구 목록 캐싱과 JSON-RPC 직렬화를 처리한다.

3단계
MCP Server

실제 비즈니스 기능(도구, 데이터 리소스, 프롬프트 템플릿)을 제공하는 독립 프로세스 또는 서버다. 언어에 구애받지 않고 유연하게 구축된다.

3. 핵심 기능 3종 (Tool · Resource · Prompt)

MCP 서버는 클라이언트에게 Tool(함수 실행), Resource(데이터 제공), Prompt(템플릿 제공)의 3가지 핵심 기능을 제공할 수 있다.

Tool (도구)
Model-Controlled

AI 모델이 필요 여부를 직접 판단하여 실행(Action)하는 함수다.

  • DB 데이터 조회 및 갱신
  • 외부 REST API 및 결제 연동
  • 로컬 파일 생성 및 셸 명령 실행
Resource (자원)
App-Controlled

AI 모델에게 제공되는 읽기 전용(Read-only) 정적/동적 컨텍스트 데이터다.

  • 고유 URI로 식별 (file://, db://)
  • 시스템 문서, API 명세서, 스키마 정보
  • 호스트 앱이 적절한 시점에 문맥에 주입
Prompt (템플릿)
User-Controlled

사전에 표준화된 재사용 가능한 프롬프트 템플릿이다.

  • 파라미터화된 메시지 구조 제공
  • 정형화된 멀티턴 대화 워크플로우 정의
  • 사용자 또는 UI가 상황에 맞게 템플릿 선택
Spring AI MCP 서버 기능 구현 코드 예시
1. Tool 등록 (JSON Schema & Handler) 
String schema = """
{
  "type": "object",
  "properties": {
    "city": { "type": "string", "description": "조회할 도시명" }
  },
  "required": ["city"]
}
""";

var weatherTool = new McpServerFeatures.SyncToolSpecification(
    new Tool("get_weather", "현재 날씨 정보 조회", schema),
    (exchange, args) -> {
        String city = (String) args.get("city");
        return new CallToolResult(List.of(new TextContent(fetchWeather(city))), false);
    }
);
2. Resource 등록 (URI 식별 읽기 전용 자원) 
var schemaResource = new McpServerFeatures.SyncResourceSpecification(
    new Resource(
        "db://schema/users",           // 고유 URI
        "users 테이블 스키마",          // 자원 명칭
        "사용자 DB 스키마 DDL 정보",     // 설명
        "text/plain", null             // MIME 타입
    ),
    (exchange, req) -> new ReadResourceResult(List.of(
        new TextResourceContents(req.uri(), "text/plain", getTableSchemaDdl())
    ))
);
3. Prompt 등록 (동적 인자 템플릿) 
var sqlPrompt = new McpServerFeatures.SyncPromptSpecification(
    new Prompt("sql-helper", "SQL 쿼리 작성 도우미", List.of(
        new PromptArgument("table", "대상 테이블명", true)
    )),
    (exchange, req) -> {
        String table = req.arguments().get("table");
        return new GetPromptResult("SQL 쿼리 작성 템플릿", List.of(
            new PromptMessage(Role.USER, new TextContent(table + " 테이블을 최적으로 조회하는 SQL을 작성해줘."))
        ));
    }
);

4. Transport 방식 비교 (STDIO vs SSE)

MCP Client와 Server 간의 통신 채널인 Transport는 배포 환경과 요구 사항에 따라 STDIO(표준 입출력)와 SSE(Server-Sent Events over HTTP) 중 선택하여 구성한다.

로컬 전용
STDIO Transport (표준 입출력)

클라이언트가 서버 프로세스를 직접 실행하고 stdin/stdout 파이프로 통신한다.

✅ 장점
  • 네트워크 오버헤드 전무 (최고 속도)
  • 포트 및 방화벽 설정 불필요
  • 로컬 개발/IDE 환경에 최적
⚠️ 제약
  • 동일 머신 내부로만 제한
  • 원격 서버 연결 불가
  • 다중 클라이언트 공유 곤란
원격/공유
SSE Transport (HTTP 스트리밍)

표준 HTTP 통신을 기반으로 POST(요청)와 Server-Sent Events(스트림 응답)를 사용한다.

✅ 장점
  • 원격 분산 서버 연결 가능
  • 다중 클라이언트 동시 접근
  • 마이크로서비스 아키텍처 적합
⚠️ 제약
  • 네트워크 지연 발생 가능
  • HTTPS 및 인증 보안 설정 필요
  • 서버 프로세스 별도 배포/관리
STDIO vs SSE 전송 방식 상세 대조
비교 항목 ⚡ STDIO 방식 🌐 SSE (HTTP) 방식
통신 매체 운영체제 표준 입출력 파이프 (stdin/stdout) HTTP POST + Server-Sent Events (SSE)
서버 위치 로컬 머신 (클라이언트의 자식 프로세스) 독립 웹 서버 / 원격 클라우드 컨테이너
다중 클라이언트 공유 어려움 (1:1 프로세스 바인딩) 매우 용이 (HTTP 엔드포인트 기반 다자 공유)
성능 및 오버헤드 초고속 (메모리 직렬화 파이프 통신) HTTP 네트워크 프로토콜 오버헤드 존재
보안 체계 OS 프로세스 격리 권한에 의존 HTTPS, API Key, JWT 토큰 인증 적용
Spring AI 클래스 StdioClientTransport HttpClientSseClientTransport

5. Spring AI 실전 구성 및 연동

의존성 추가부터 클라이언트 설정, 그리고 ChatClient에 MCP 도구를 자동으로 연계하는 단계별 실전 구현 과정이다.

Step 1
Maven 의존성 설정 (pom.xml)

클라이언트(Host 앱) 또는 서버 역할에 맞추어 Starter 의존성을 추가한다.

<!-- 1. MCP 클라이언트 Starter (Host 애플리케이션) -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-mcp-client-spring-boot-starter</artifactId>
</dependency>

<!-- 2. MCP 서버 Starter (Spring Boot WebMVC 기반) -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-mcp-server-webmvc-spring-boot-starter</artifactId>
</dependency>
Step 2
클라이언트 연결 설정 (application.yml)

연결할 외부 MCP 서버 목록을 정의한다. STDIO와 SSE 방식을 자유롭게 혼용할 수 있다.

spring:
  ai:
    mcp:
      client:
        enabled: true
        toolcallback:
          enabled: true   # MCP 도구를 ChatClient에 자동으로 주입
        connections:
          # 로컬 STDIO 방식 서버 연결
          local-weather-server:
            type: STDIO
            command: java
            args: ["-jar", "weather-mcp-server.jar"]
          # 원격 SSE 방식 서버 연결
          remote-search-server:
            type: SSE
            url: http://search-mcp-service:8080
Step 3
ChatClient에서 MCP 도구 자동 활용

ToolCallbackProvider를 주입받아 등록하면, AI 모델이 대화 맥락에 따라 필요한 MCP 도구를 자율적으로 호출한다.

@Service
public class ChatService {

    private final ChatClient chatClient;

    public ChatService(ChatClient.Builder builder, ToolCallbackProvider mcpTools) {
        this.chatClient = builder
            .defaultTools(mcpTools)   // 모든 MCP 서버의 도구를 원스톱 자동 등록
            .build();
    }

    public String ask(String userQuery) {
        return chatClient.prompt()
            .user(userQuery)
            .call()
            .content();  // 필요시 MCP Server의 도구를 백그라운드 호출 후 종합 답변 반환
    }
}
Spring AI MCP 핵심 요약

Spring AI의 toolcallback.enabled: true 옵션을 통해 복잡한 JSON-RPC 통신과 직렬화 과정을 완전히 추상화할 수 있다. 개발자는 비즈니스 로직 및 도구 구현에만 집중하며 확장성 높은 엔터프라이즈 AI 시스템을 구축할 수 있다.
