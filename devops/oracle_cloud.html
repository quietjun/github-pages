Oracle Cloud Always Free 기반 Spring Boot 호스팅 가이드

OCI(Oracle Cloud Infrastructure) Ampere ARM 아키텍처 환경에서 Spring Boot 및 MySQL 서비스를 무중단으로 안정 배포하는 엔지니어링 표준 절차를 정의한다.

1. 인프라 아키텍처 개요

클라이언트의 HTTP 요청이 가비아 DNS와 OCI 네트워크 계층을 거쳐 Spring Boot 애플리케이션 및 MySQL에 도달하는 트래픽 처리 흐름은 다음과 같다.

2. OCI 콘솔 한글화 & ARM 인스턴스 사양

작업 효율을 높이기 위해 OCI 콘솔 언어를 한국어로 전환한 후, Oracle Cloud Always Free 티어에서 제공하는 최대 가용 리소스를 활용하여 고성능 ARM 인스턴스를 프로비저닝한다.

사전 설정: OCI 웹 콘솔 한국어(Korean) 변경 절차
언어 변경 경로

인스턴스 생성 5단계 프로세스 가이드

OCI 콘솔 상단 컴퓨트 ➔ 인스턴스 ➔ 인스턴스 생성 메뉴로 이동한 뒤 아래 5개 섹션 순서대로 설정을 진행한다.

Step 1
기본 정보 (Name, Image & Shape)
  • 이름: 인스턴스 명칭 입력 (예: spring-server)
  • 배치: 가용성 도메인(AD) 기본값 유지
  • 이미지: Canonical Ubuntu 22.04 선택
  • 셰이프(Shape): Ampere ARM ➔ VM.Standard.A1.Flex 지정 (2 OCPU / 12GB RAM 할당)
Step 2
보안 (Security Options)
  • 실드된 인스턴스: 비활성화(끔) 유지 (기본값)
  • 기밀 컴퓨팅: 비활성화(끔) 유지 (ARM VM 미지원/비호환)
  • 별도 변경 없이 하단의 [다음] 버튼을 눌러 이동
Step 3
네트워킹 & SSH 키 (Networking & Keys)
  • 기본 네트워크: 기존 가상 클라우드 네트워크 선택 및 기존 서브넷 선택 (기본값 유지)
  • 프라이빗 IPv4: 자동으로 프라이빗 IPv4 주소 지정 (기본값 유지)
  • 퍼블릭 IPv4 지정: 자동으로 퍼블릭 IPv4 주소 지정 토글 [켜짐(활성화)] 필수 확인
  • IPv6 주소 지정: 서브넷 풀에서 IPv6 주소 지정 토글 [꺼짐(비활성화)] 유지
  • SSH 키 추가: 자동으로 키 쌍 생성 선택 ➔ [프라이빗 키 다운로드] 및 [퍼블릭 키 다운로드] 버튼 각각 클릭하여 안전 보관
Step 4
스토리지 (Boot Volume)
  • 부트 볼륨 크기: 기본값 47 GB 유지 (Always Free 200GB 한도 내 무료)
  • 성능: 기본 VPU(10 VPU) 유지
  • 암호화: Oracle 관리 키 기본값 유지
Step 5
검토 (Review & Create)
  • 입력한 기본 정보, 보안, 네트워킹, 스토리지 설정을 최종 검토한 후 하단의 [생성(Create)] 버튼 클릭
  • 인스턴스 상태가 프로비저닝 중(Provisioning)에서 실행 중(Running)으로 바뀐 후 할당된 공용 IP(Public IPv4)를 확인
트러블슈팅
인스턴스 생성 시 "용량 부족(Out of Capacity)" 오류 대처법

생성 버튼 클릭 시 "가용성 도메인 VM.Standard.A1.Flex에서 AD-1 셰이프에 대한 용량이 부족합니다(Out of Capacity)"라는 API 오류가 발생하는 경우, Always Free ARM 물리 서버 자원이 실시간으로 소진된 상태이다. 아래 4가지 방법으로 즉시 대처할 수 있다.

1. 가용성 도메인(AD) 변경 (가장 빠름 ★)

도쿄(Japan East) 등 멀티 AD 리전의 경우 Step 1 ➔ [배치]로 돌아가 AD-1 대신 `AD-2` 또는 `AD-3`를 선택 후 재생성한다.

2. 결함 도메인(Fault Domain) 변경

서울/춘천 등 단일 AD 리전은 [배치] ➔ [고급 옵션]에서 결함 도메인을 FD-1, FD-2, FD-3로 변경하며 시도한다.

3. 셰이프 자원 일시 축소 후 생성

처음부터 2 OCPU / 12GB 대신 1 OCPU / 6GB RAM으로 우선 생성한 뒤, 인스턴스 생성 후 [편집] 메뉴에서 2 OCPU / 12GB로 스케일업한다.

4. 자원 반납 시간대(새벽) 재시도

사용자들의 자원이 회수 및 재배치되는 새벽 또는 이른 아침 시간대에 다시 시도하면 원활하게 생성된다.

3. SSH 접속 및 Swap 메모리 최적화

다운로드한 SSH 전용 키의 접근 권한을 400으로 제한하고 인스턴스에 접속한 뒤, 대용량 트래픽 급증 시 시스템 다운을 예방하기 위해 4GB 가상 메모리(Swap)를 할당한다.

1. SSH 터미널 접속
# SSH 전용 키 권한 제한 (Linux / macOS 필수)
chmod 400 private_key.key

# Ubuntu 원격 인스턴스 접속
ssh -i private_key.key ubuntu@[서버_공용_IP]
2. 4GB Swap 가상 메모리 생성 및 영구 마운트
# 4GB 크기의 스왑 파일 할당
sudo fallocate -l 4G /swapfile

# 파일 읽기/쓰기 보안 권한 부여
sudo chmod 600 /swapfile

# 스왑 영역 포맷 및 활성화
sudo mkswap /swapfile
sudo swapon /swapfile

# 부팅 시 자동 마운트를 위한 /etc/fstab 등록
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

4. Java 21 및 MySQL 8 환경 구축

Spring Boot 구동을 위한 최신 LTS OpenJDK 21과 관계형 데이터베이스 MySQL 8.0을 설치하고 사용자 권한을 구성한다.

1. OpenJDK 21 설치 및 버전 확인
# 패키지 인덱스 갱신 및 OpenJDK 21 설치
sudo apt update
sudo apt install openjdk-21-jdk -y

# 설치된 Java 버전 및 아키텍처 검증
java -version
2. MySQL Server 설치 및 계정 권한 설정
-- MySQL 서버 패키지 설치 및 루트 셸 진입
-- (Bash 실행: sudo apt install mysql-server -y && sudo mysql)

-- 데이터베이스 생성
CREATE DATABASE ssafy_db;

-- 원격 접속 계정 생성 및 비밀번호 지정
CREATE USER 'quietjun'@'%' IDENTIFIED BY 'dmstj@0205M';

-- 데이터베이스 전체 권한 부여
GRANT ALL PRIVILEGES ON ssafy_db.* TO 'quietjun'@'%';

-- 권한 테이블 즉시 갱신 및 종료
FLUSH PRIVILEGES;
EXIT;

5. 포트 포워딩 및 DNS 도메인 연동

Nginx와 같은 리버스 프록시 서버 없이도 사용자가 포트 번호(:8080) 없이 접속할 수 있도록 iptables 포트 리다이렉션을 구성하고 DNS A 레코드를 연결한다.

1. iptables 80 ➔ 8080 포트 리다이렉션 및 영구 저장
# 외부 80번(HTTP) 포트 요청을 로컬 8080번 포트로 리다이렉트
sudo iptables -t nat -I PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT

# 서버 재부팅 후에도 방화벽 규칙이 유지되도록 영구 저장
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
2. 가비아(Gabia) DNS 레코드 등록
DNS 설정 항목
타입: A / 호스트: @

값 위치에 OCI 인스턴스의 공용 IPv4 주소를 입력하여 도메인을 바인딩한다.

접속 테스트
http://[사용자도메인]

포트 번호(:8080) 입력 없이 표준 HTTP 접속 시 Spring Boot 서비스로 자동 연결된다.

6. systemd 서비스 상시 가동 등록

서버 재부팅 및 프로세스 예기치 않은 종료 시에도 자동으로 재시작될 수 있도록 systemd 서비스 유닛을 생성하여 데몬으로 등록한다.

1. 서비스 유닛 파일 생성 (/etc/systemd/system/myapp.service)
[Unit]
Description=Spring Boot Application
After=network.target

[Service]
User=ubuntu
ExecStart=/usr/bin/java -jar /home/ubuntu/app.jar
SuccessExitStatus=143
Restart=always

[Install]
WantedBy=multi-user.target
2. 서비스 활성화 및 백그라운드 구동
# 부팅 시 자동 시작 등록 및 서비스 즉시 구동
sudo systemctl enable myapp
sudo systemctl start myapp

# 서비스 상태 확인
sudo systemctl status myapp

7. ARM 아키텍처 운영 주의사항

주의사항
ARM 아키텍처(Aarch64) 바이너리 호환성

OCI Always Free 인스턴스는 Ampere Aarch64 (ARM 64비트) 프로세서를 탑재하고 있다.

  • 순수 Java 애플리케이션: JVM 바이트코드 기반으로 동작하므로 아키텍처와 무관하게 100% 정상 작동.
  • JNI / Native 라이브러리 사용 시: C/C++ 기반 바이너리가 포함된 라이브러리(예: 특정 암호화 모듈, SQLite 네이티브 등)를 사용할 경우, x86_64 전용 빌드가 아닌 ARM64 바이너리가 포함되어 있는지 빌드 단계에서 사전 점검 필요.

핵심 요약

  • 무료 리소스 최적 활용: OCI Always Free ARM 인스턴스(2 OCPU, 12GB RAM, 47GB+ 디스크)로 고성능 인프라 확보
  • 안정성 극대화: 4GB Swap 가상 메모리 생성 및 영구 마운트로 메모리 버퍼 확보
  • 간소화된 라우팅: Nginx 없이 iptables NAT PREROUTING을 통해 80번 포트를 8080번으로 리다이렉션
  • 데몬 자동 복구: systemd 서비스를 통해 서버 재부팅 및 크래시 시 무중단 자동 재시작 환경 구축
