GCP 3-Tier 구축 가이드 (무료 플랜 실무형)

네트워크 망 분리 + Multi-AZ 구조를 100% 무료 리소스(H2, Nginx)로 시뮬레이션 해보기

🏗️ GCP Free Tier Architecture (실무 시뮬레이션)

💡 실무 아키텍처와 무료 시뮬레이션의 차이점
이 가이드는 망 분리(VPC/Subnet), 다중 가용영역(Multi-AZ) 같은 실무형 네트워크 뼈대는 그대로 가져가되, 비용이 발생하는 Cloud SQL이나 L7 로드밸런서, Cloud NAT 대신 Nginx, H2 DB, 임시 외부 IP 등 100% 무료 우회 기술을 사용하여 요금 폭탄을 방지합니다. (참고: GCP 평생 무료 `e2-micro`는 리전당 1대이므로, 3대 사용 시 월 약 $10 정도의 요금이 발생할 수 있으나, 가입 시 제공되는 $300 크레딧에서 차감됩니다.)
1
실무형 망 분리 (VPC & Subnet)
🎯 이 단계의 목표 모든 인프라의 기반이 되는 격리된 네트워크 망(Custom VPC)을 구축합니다. Nginx용 망과 백엔드(Spring Boot)용 망을 논리적으로 분리합니다.

Step 1-1: Custom VPC 생성

  • VPC 네트워크 → VPC 네트워크 생성
    - 이름: `free-prd-vpc`
    - 서브넷 생성 모드: 맞춤설정(Custom)
  • 계층별 서브넷(Subnet) 구성
    보안을 위해 역할을 분리하여 2개의 서브넷을 생성합니다. (리전은 모두 무료 티어인 us-central1 사용)
    서브넷 이름 IP 범위 용도 (티어)
    free-snet-web 10.250.1.0/24 Nginx LB (Frontend)
    free-snet-was 10.250.2.0/24 Spring Boot (Backend)

Step 1-2: IAP 및 기본 방화벽 설정

  • IAP 방화벽 오픈 (중요)
    나중에 생성할 외부 IP가 없는 Private WAS에 안전하게 접속하기 위해 필수입니다.
    VPC 네트워크 → 방화벽 → 방화벽 규칙 만들기
    - 이름: `allow-iap-ssh`
    - 네트워크: `free-prd-vpc`
    - 소스 IPv4 범위: 35.235.240.0/20 (구글 IAP 대역)
    - 프로토콜/포트: TCP 22
  • 내부 망 통신 및 HTTP 허용
    - 규칙 1 (`allow-http`): 소스 `0.0.0.0/0`, TCP 80, 443 (웹 서버용)
    - 규칙 2 (`allow-internal-vpc`): 소스 `10.250.0.0/16`, TCP 8080 (내부 로드밸런싱 통신용)
2
Nginx 로드밸런서 (비싼 ALB 대체)
🌐 역할: 글로벌 트래픽 인입 및 라우팅 유료인 GCP External ALB 대신, Nginx가 설치된 VM에 공인 IP를 달아 외부 요청을 뒷단의 Private 서버들로 분산(로드밸런싱)시킵니다.

Step 2-1: Nginx 인스턴스 배포

  • Compute Engine → 인스턴스 → 만들기
    - 이름: `nginx-lb-vm`
    - 리전/영역: `us-central1` / `us-central1-a`
    - 머신 유형: `e2-micro`
    - 네트워크: `free-prd-vpc` / 서브넷: `free-snet-web`
    - 외부 IPv4 주소: 임시 또는 고정 (외부에서 접근해야 하므로 필수)
  • VM 접속 후 Nginx 설치:
    $ sudo apt-get update $ sudo apt-get install -y nginx
  • Nginx 설정은 뒷단 WAS 서버들의 IP를 확보한 뒤, Step 3 이후에 구성합니다.
3
백엔드 계층 (Spring Boot Multi-AZ)
⚙️ 역할: 서버 이중화 및 내장 DB(H2) 시뮬레이션 유료인 Cloud SQL 대신, Spring Boot 앱 안에 내장된 H2를 각각 실행합니다. A존과 C존에 분산 배치하여 고가용성 구조를 실습합니다.

Step 3-1: WAS 인스턴스 2대 배포 (NAT 꼼수)

⚠️ 외부 IP 임시 할당 꼼수: 원래 외부 IP가 없는 VM이 인터넷(apt-get 등)을 쓰려면 유료인 Cloud NAT가 필요합니다. 무료로 하려면 VM 생성 시 임시 외부 IP를 부여하고, 세팅 완료 후 외부 IP를 떼어내는 방식을 사용하세요.
  • VM 1 (Zone A)
    - 이름: `free-was-a` (영역: `us-central1-a`)
    - 서브넷: `free-snet-was`
    - 외부 IP: 임시 할당 (설치 완료 후 수정에서 '없음'으로 변경할 것)
  • VM 2 (Zone C)
    - 이름: `free-was-c` (영역: `us-central1-c`)
    - 서브넷: `free-snet-was`
    - 외부 IP: 임시 할당

Step 3-2: Java 설치 및 H2 Spring Boot 실행

  • 외부 IP가 붙어있을 때 각 VM에 접속하여 Java를 설치합니다.
    $ sudo apt-get update $ sudo apt-get install -y openjdk-21-jre
  • 로컬에서 컴파일한 H2 포함 `.jar` 파일을 전송합니다.
    $ gcloud compute scp app.jar free-was-a:~/ --zone=us-central1-a $ gcloud compute scp app.jar free-was-c:~/ --zone=us-central1-c
  • 전송 후 백그라운드에서 실행(`nohup java -jar app.jar &`)한 뒤, VM 수정 화면으로 가서 외부 IP를 반드시 '없음'으로 변경합니다! (보안 강화 완수)
4
로드밸런싱 연동 및 테스트

Step 4-1: Nginx 프록시 구성

  • 다시 nginx-lb-vm 에 접속하여 `/etc/nginx/sites-available/default` 파일을 수정합니다.
    upstream backend_was { server 10.250.2.x:8080; # free-was-a의 실제 내부 IP 입력 server 10.250.2.y:8080; # free-was-c의 실제 내부 IP 입력 } server { listen 80; location /api/ { proxy_pass http://backend_was; } }
  • Nginx를 재시작합니다. (`sudo systemctl restart nginx`)

Step 4-2: 최종 검증

  • 데이터 격리 확인
    브라우저나 curl로 Nginx의 외부 IP(`http://[NGINX_외부_IP]/api/users`)를 여러 번 호출해보세요.
    H2 데이터베이스는 각 VM 메모리에 독립적으로 존재하므로, 로드밸런싱으로 인해 요청이 A존과 C존을 번갈아 타면서 반환되는 데이터가 다를 것입니다. 이것이 우리가 의도한 "가짜 이중화" 시뮬레이션의 핵심입니다!
🎉 무료 플랜 아키텍처 완성!
